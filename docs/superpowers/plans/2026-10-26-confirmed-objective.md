# 확정 목표물 평가 기준 반영 계획

기록일: 2026-10-26. 사용자 요청과 [D24](../decisions/2026-10-22-overnight-decisions.md#d24--2026-10-24-목표물-공격-평가-기준-사용자-확정)를 실행하는 계획이다. 제품 규칙은 [평가 정본](../../spec.md#경기별-활약-점수)을 따른다.

| 분류·상태 | 주체 | 이번 실행 선택 | 지금 판단할 사항 |
| --- | --- | --- | --- |
| 사용자 확정·유지 | 사용자 | 포지션별 지표와 원본 보존 | 없음 |
| 위임받은 선택·구현 예정 | 실행 담당자 | 새 알고리즘 `objective-position-v1`, 기존 선택 규칙의 가중치를 복사하는 DB 이전 | 없음. 기존 기준 구현 요청에 포함 |
| 조사 및 검증·예정 | 실행 담당자 | 실제 PostgreSQL에서 이전·전체 재계산, 기존 G1–G3 수치, 실제 HTTP·브라우저 확인 | 결과는 별도 검증 보고서에 기록 |

**구조:** 기존 계산 수식은 유지한다. Flyway(데이터베이스 변경을 순서대로 적용하는 도구)의 V4 이전으로 선택된 임시 규칙을 새 ID에 복사하고 입력 변경 번호·영속 작업을 함께 만든다. 과거 규칙·평가와 경기 원본은 변경하지 않는다. 신규 DB는 확정 기본 규칙으로 시작한다.

**비교:** 시작 시 작업자에서 변환하면 조회가 먼저 열려 잠시 과거 점수를 공개할 수 있다. DB 이전은 서버가 조회를 받기 전에 전환하고 트랜잭션으로 실패를 되돌릴 수 있어 선택했다. 비용은 DB 이전 코드와 호환성 검증이며, 지표·정규화 구현을 바꿀 때 재검토한다.

## 실행 순서

- [x] `ScoringServiceTest`에 다섯 포지션의 지표 선택·분당 환산 검증을 보완한다. 새 기본 버전 및 과거 버전 신규 생성 거절 테스트를 먼저 실패시킨다. `ScoringRulesV1`과 `EvaluationRepository.createRules`에서 기본 버전과 입력 검사를 바꾼다.
- [x] `ConfirmedScoringMigrationIntegrationTest`에서 이전 기본/조정 규칙, 이전 점수 차단, 원본·과거 세대 보존, 중복 실행·빈 DB·확정 규칙 유지, G1–G3 전체 재계산을 검증한다. 이전 전용 테스트를 먼저 실패시킨 뒤 `V4__confirmed_objective.sql`을 구현한다. 실패 시 부분 반영을 남기지 않는지도 확인한다.
- [x] `Common.tsx`·운영자 평가 화면·현재 API 설명·JSON 스키마를 맞춘다. `tests/web`에서 새 버전 규칙 조회·저장·전체 재계산과 설명을 실제 서버로 확인하고 결과 이미지를 저장한다.
- [x] 서버 전체 빌드, Node 검사, 관련 브라우저 검사, 형식·문서 검사를 실행한다. 결정 기록·현재 상태·검증 보고서를 대조하고 정본 목록과 안내표를 갱신한다.

## 검토 초점

- 조정된 가중치와 내부 비율을 기본값으로 되돌리지 않는다.
- 과거 규칙 조회는 호환하되 임시 알고리즘의 새 선택은 거절한다.
- 취소·확인 대기 경기를 새 세대에 넣지 않는다.
- 이전 세대 작업의 늦은 게시를 입력 변경 번호와 버전으로 차단한다.
- 실측 수치는 보존하되 G1–G3의 테스트 포지션은 실제 포지션 검증으로 표현하지 않는다.

작업 공간은 변경 없는 현재 체크아웃을 사용한다. 별도 배포 대상·운영 DB 접속 정보는 제공되지 않았으므로 로컬 검증과 배포 시 자동 이전 구현을 구분해 보고한다. 제외된 Windows 실험·시범 운영은 이 계획에 포함하지 않는다.
