# 수집기 솔로랭크 기능 제거와 팀 추천 확인 계획

> 실행 담당자는 이 대화에서 직접 작업한다. 사용자 요청은 수집기 기능 제거와 현재 팀 추천 검증이며, 솔로랭크 서버 연동의 신규 구현은 이번 범위가 아니다.

기록일·편집일: 2026-10-29. 사용자의 작업 위치 지시에 따라 `master`에서 `codex/participant-collector-ux`의 기존 작업 폴더로 이동했다. 이 브랜치의 선행 UX·등급 보정 구현을 유지하며, 최초 master 실행은 이전 검증 기록으로 구분한다. 목표는 수집기에서 불필요한 기능을 없애고, 웹 팀 추천에서 내전 표본이 부족할 때 실제로 사용하는 자료를 확인하는 것이다. 제품 기준은 [명세](../../spec.md#포지션별-실력-보정), 변경 이유는 [사용자 결정 보완](../decisions/2026-10-28-ux-requirements.md#2026-10-29-보완--솔로랭크는-웹-팀-추천에서만-사용)을 따른다.

## 범위와 방법

- 기존 Electron·React 수집기의 화면, 화면과 내부 처리 간 통신(IPC), 사전 로드 연결에서 솔로랭크 내보내기를 제거한다. 로컬 DB·수집·등록 처리는 바꾸지 않는다.
- Java 서버의 팀 추천 요청 → 평가 자료 → 포지션별 실력 계산을 추적한다. 운영 자료 대신 격리 PostgreSQL의 합성 회원과 보관 경기 시험 자료를 쓴다.
- 기존 문서의 미커밋 변경을 보존하며 정본의 목표와 현재 구현을 구분한다. 외부 Riot 호출 성공이나 Windows 배포 완료를 주장하지 않는다.

## 작업 1: 수집기 연결 제거

대상: `apps/collector/src/renderer/App.tsx`, `preload/collector-api.ts`, `preload/index.ts`, `main/ipc.ts`, `main/main.ts`, `main/reference-export.ts`.

- [x] 기존 IPC 입력 검증 시험에서 제거할 `references` 명령의 거절을 추가하고, 현재 구현이 이를 허용해 실패하는지 확인한다.
- [x] 버튼·공개 호출·명령·고정 실패 구현을 함께 제거한다. 정상 명령은 기존 입력 검증을 계속 통과한다.
- [x] `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`를 실행한다. Electron의 경기 조회·등록 흐름과 제거 후 화면을 확인하고 새 날짜의 이미지를 남긴다.

## 작업 2: 내전 기록이 부족한 팀 추천 검증

대상: `apps/server/src/test/java/cw/teams/TeamApiIntegrationTest.java`. 제품 서버 코드는 이번 조사에서 바꾸지 않는다. 선행 구현의 공식 등급 조회 경계만 가상 응답으로 주입한다.

- [x] 내전 0경기에서 가상 솔로랭크 등급이 팀 추천 시작값에 사용되는지 확인한다.
- [x] 내전 1경기에서 해당 포지션 점수와 솔로랭크 시작값의 기존 다섯 경기분 보정이 계산에 반영되는지 확인한다.
- [x] 솔로랭크 포지션 표본을 가져오기 전후에 팀 추천 입력·결과가 바뀌는지 대조한다. 등급 자동 조회와 포지션 제안을 혼동하지 않는다.
- [x] 실제 PostgreSQL 통합 시험과 웹 브라우저 추천 시험을 실행한다. 실행 환경·결과·외부 연동 한계는 [검증 보고서](../../validation/2026-10-29-team-solo-report.md)에 기록한다.

## 작업 3: 문서 대조와 완료 확인

- [x] 제품 명세·현재 계약·현재 상태·개발 안내를 대조하고 수집기 제거를 미완료 작업으로 남기지 않는다. 예전 측정값과 실행 결과는 보존한다.
- [x] `pnpm docs:index`, `pnpm test:docs`, `pnpm docs:check`, 형식 검사를 실행한다.
- [x] 최종 변경을 검토하고 제거 완료와 팀 추천의 미구현·미검증 사항을 나눠 보고한다.
