# 밝은 화면과 참가자 프로필 사진 구현 계획

> **실행 방식:** `superpowers:executing-plans`에 따라 서버 사진 조회부터 화면 검토까지 네 작업을 순서대로 진행한다. 완료 항목은 아래 체크 표시로 기록했다.

**Goal:** 웹과 수집기에서 같은 밝은 디자인으로 기록을 확인하고, 참가자의 현재 Riot 프로필 사진으로 사람을 쉽게 구분한다.

**Architecture:** 기존 참가자·수집기 브랜치의 현재 작업을 별도 작업 폴더에 보존한 뒤 구현한다. 공식 계정 조회와 Summoner API로 프로필 아이콘 번호를 서버에서 갱신·보관하고 웹에는 번호만 제공한다. 화면 조회는 저장된 값을 사용하며 외부 조회를 기다리지 않는다.

**Tech Stack:** 저장소의 Java·Spring·PostgreSQL, React·TypeScript·Electron과 기존 시험 도구를 유지한다. 버전은 설정 파일이 원본이다.

**Spec:** [현재 제품 기준](../../spec.md#화면-디자인과-참가자-사진), [선택 이유와 위임 기록](../decisions/2026-10-29-light-ui.md).

## Global Constraints

- 사용자 확정 화면·사진 요구를 적용한다. 실제 운영 배포와 제외된 Windows 실기를 새 완료 조건으로 넣지 않는다.
- 기존 경기·참가자·인증·수집기 저장 구조를 보존한다. 프로필 캐시는 별도 테이블에 추가한다.
- Riot 비밀 키와 계정 식별값은 사진 표시 응답·URL에 넣지 않는다. 경기의 참가자 사진은 기존 챔피언 초상화를 유지한다.
- 등록된 내전과 자동 재시도를 보존하고, 수집기의 솔로랭크 참고 기능을 되살리지 않는다.

## Review Focus

- Riot ID 변경 중 늦게 도착한 외부 응답은 다른 사람의 사진으로 저장하지 않는다(T1).
- 사진 조회 실패·키 없음·외부 이미지 오류는 마지막 정상 사진 또는 이름 기반 대체 표시로 처리하며 참가자 목록을 막지 않는다(T1·T2).
- 수집기의 작은 창에서도 양 팀 순서와 포지션 선택·K/D/A의 가독성을 유지한다(T3).
- 하단 페이지 전환 뒤 초점과 경기 위치를 잃지 않고 포지션 초안을 보존한다(T3).
- 긴 참가자 이름·계산 중·빈 목록·키보드 탐색에서 밝은 화면의 내용과 조작이 겹치지 않는다(T4).

### Task 1: 서버 프로필 아이콘 조회와 보관

**Files:** `cw/riot/RiotGateway.java`, `HttpRiotGateway.java`, 새 `MemberProfileService.java`, `MemberProfileSnapshot.java`, `MemberProfileRepository.java`, 기존 스케줄러·참가자 서비스·응답 계약, 새 DB 이전. 시험은 `HttpRiotGatewayTest`, `MemberProfileIntegrationTest`.

**Interfaces:** `getProfileIcon(String officialPuuid)`는 상태·아이콘 번호·재시도 지연을 반환한다. `MemberProfileService.refresh(memberId)`는 외부 조회 후 현재 Riot ID를 다시 확인한다. `icon(memberId, riotId)`는 캐시만 읽고 번호 또는 null을 반환한다.

- [x] 공식 경로·헤더 키·유효/잘못된 번호·제한 응답과 마지막 정상 사진 보존·Riot ID 변경·공개 응답의 식별값 비노출 검사를 먼저 작성해 실패를 확인한다.
- [x] 별도 캐시와 기존 외부 요청 제한을 사용한다. 스케줄러가 순서대로 갱신하고 공개 조회는 외부 통신 없이 동작하게 한다.
- [x] 격리 PostgreSQL에서 관련 Java 시험을 통과시키고 커밋한다.

### Task 2: 웹 밝은 디자인과 사진 표시

**Files:** 웹 공통 스타일·`MemberAvatar.tsx`·참가자 목록/관리/프로필/팀 추천·경기 목록·앱 바닥글, API 스키마. 시험은 `tests/web/light-ui.spec.ts`와 기존 공개 웹 검사.

**Interfaces:** 공개·관리 참가자 응답의 `profileIconId`를 공통 사진 컴포넌트가 기존 자산 버전과 함께 사용한다. 사진 실패 시 이름 첫 글자를 같은 크기로 표시한다.

- [x] 웹 사진·실패 대체·챔피언 사진 유지·두 필터 제거·바닥글 검사를 먼저 추가하고 실패를 확인한다.
- [x] 밝은 색·글자·간격 기준을 두 앱 공통 CSS에서 관리하고 웹의 기존 상태·표·입력을 적용한다. 사진을 참가자 목록·관리·팀 선택/결과에 표시한다.
- [x] 기존 페이지·필터·관리 동작 검사와 새 웹 검사를 통과시키고 커밋한다.

### Task 3: 수집기 좌우 배치와 하단 페이지

**Files:** 수집기 `App.tsx`, `MatchList.tsx`, `MatchReview.tsx`, `styles.css`, 웹과 공유하는 페이지 컴포넌트. 시험은 `tests/e2e/collector.spec.ts`.

**Interfaces:** 공통 페이지 UI는 이전·현재 페이지·다음의 순서와 비활성 조건을 공유한다. 수집기는 페이지당 세 경기를 유지한다.

- [x] 하단 위치·이전/현재/다음·좌우 팀 경계·검증 대기 문구 제거·초안 보존을 확인하는 Electron 검사를 먼저 추가해 실패를 확인한다.
- [x] 요청한 배치와 문구를 반영하고 작은 화면에는 행 내부 배치를 조정한다. 페이지 전환은 목록 시작으로 이동하고 선택한 포지션은 유지한다.
- [x] Electron 가상 응답 검사와 빌드를 통과시키고 커밋한다.

- [x] 발견한 사용자 영향을 수정하고 관련 회귀 검사를 실행한다. 화면 이미지를 저장한다.

- [x] 별도 검토자의 중요한 지적을 처리하고 최종 결과·미확인 실연동·운영 반영 범위를 구분해 기록한다.
