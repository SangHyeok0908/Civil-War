# Windows 수집기 설치 파일 구현 계획

> **실행 담당자:** `superpowers:executing-plans`로 순서대로 구현한다. 사용자 요청은 이미 설명한 설치 파일 제작이며 설치·업데이트 보존 시험 전체의 완료 요청과 구분한다.

**목표:** 개발 도구 없이 설치할 Windows x64 수집기 설치 파일과 무결성 확인값을 전달한다.

**구조:** 기존 Electron 빌드 결과만 허용 목록으로 포장하고, NSIS 설치기를 사용한다. 사용자별 설치 식별자를 고정하고 앱 제거에서 자료 삭제를 비활성화한다. 경기·인증 저장 코드와 기존 저장 경로는 변경하지 않는다.

**기술:** 기존 Electron·esbuild·Vite와 정확한 버전으로 고정한 electron-builder.

**명세:** [설치·운영 기준](../../spec.md#설치운영-설계). 제품 규칙은 이 계획에 복제하지 않는다.

## 범위와 판단

| 분류 | 주체·상태 | 이번 적용 | 지금 판단할 사항 |
| --- | --- | --- | --- |
| 사용자 확정 | 사용자, 설치 파일 제작 요청 | 자료 보존 시험에 앞서 설치판 제공 | 없음 |
| 위임받은 선택 | 구현 담당자 | x64·사용자별 NSIS 설치, 서명 없는 시험 배포, 자동 게시 없음 | 다른 CPU 지원은 이번 산출물에 포함하지 않음 |
| 조사 및 검증 | 구현 담당자 | macOS 교차 빌드와 포장 내용 검사. Windows 설치 실행 여부는 증거대로 기록 | 생성 성공을 실제 자료 보존 확인으로 표현하지 않음 |

## 검토 중점

- 비공개 원본·시험 응답·개발 의존성이 설치판에 불필요하게 포함되지 않는지 검사한다.
- 경로에 공백이 있어도 빌드·배포 파일 검증이 가능한지 확인한다.
- 사용자가 이미 편집한 AGENTS.md는 이 작업에 섞어 수정하거나 커밋하지 않는다.
- 지원 런타임의 SQLite가 포함되는지 확인한다. 당시 계획의 외부 SQLite 모듈 재빌드 지시는 현재 내장 `node:sqlite` 구현에 그대로 적용하지 않는다.
- 서버 기본 연결과 변경 방법을 안내하고, 설치 완료만으로 운영 서버 연결 성공이라고 하지 않는다.

## 작업 1: 설치판과 배포 검증

**파일:** 설치 설정, `scripts/package-collector.mjs`, 배포 검증 테스트, 루트 명령·잠금 파일, 설치 안내·검증 보고서·현재 상태·정본 목록.

**입력:** 기존 `scripts/build-collector.mjs`의 main/preload/renderer 출력.

**출력:** `dist/collector/`의 버전이 표시된 설치 실행 파일, SHA-256 목록과 산출물 메타데이터. 자동 업로드나 GitHub Release는 만들지 않는다.

- [x] 배포 검사에서 누락·변경된 파일과 잘못된 버전을 거절하는 테스트를 먼저 실행해 실패를 확인한다.
- [x] electron-builder 설정과 패키징·해시 생성·재검증 명령을 구현한다.
- [x] 실제 Windows 실행 파일을 만들고 포장 허용 목록·PE 형식·해시를 확인한다.
- [x] 기존 단위 검사·형식·타입·Electron 흐름·문서 검사를 실행한다.
- [x] 생성·실행·자료 보존의 확인 범위를 분리해 안내·보고서를 갱신하고 변경 전체를 검토한다.

## 후속 범위

설치판의 실제 Windows 실행, 이전 설치판에서의 업데이트·제거 후 재설치와 인증 보호 복구는 [현재 상태](../../status.md)에 남긴다. 새 내전이나 제외한 시범 운영을 조건으로 추가하지 않는다.
