# Windows 자료 보존·인증 복구 시험 준비 계획

기록일·편집일: 2026-10-26. 사용자가 요청한 네 가지 시험을 실행할 수 있도록 배포 묶음·업데이트판·실행 절차를 준비한다. Windows 조작과 실제 서버 배포는 사용자가 맡으며, 로컬 준비 성공을 실기 성공으로 기록하지 않는다.

**목표:** 첫 설치판에서 기기 등록, 대기 자료 생성, 재실행·재설치·버전 업데이트, 인증 손상 복구를 순서대로 확인할 준비를 마친다.

**구조:** 기존 Windows 데스크톱·Docker Desktop·Cloudflare Tunnel 운영 합의를 따른다. 자동 검사가 초기화하는 DB와 별도의 시험 DB·볼륨을 둔다. 수집기는 버전만 올려 첫 버전과 같은 저장 경로·설치 식별자의 업데이트판을 만든다.

**기술:** 기존 Java 서버 JAR·PostgreSQL·Electron 설치기. 버전·이미지 해시는 설정 원본을 따른다.

**기준:** [설치·운영 명세](../../spec.md#설치운영-설계), [오프라인 보존 명세](../../spec.md#오프라인-대기와-재시도). 상세 실행 순서는 각각의 운영 안내에만 둔다.

## 실행 범위

| 분류·상태 | 주체 | 판단 | 지금 판단할 사항 |
| --- | --- | --- | --- |
| 사용자 확정 | 사용자 | 네 가지 후속 시험 요청, 실제 배포·Windows 조작 직접 수행 | 없음 |
| 사용자 확정 | 사용자, 기존 합의 재확인 | 집 Windows·Docker Desktop·Cloudflare 사용 | 배포 환경을 다시 선택하지 않음 |
| 위임받은 선택 | 실행 담당자 | 시험 전용 Compose와 자료 보존 비교용 업데이트판 제공 | 실기 결과에 따라 수정 |

## 검토 중점

- 자동 시험용 DB와 이름·볼륨이 섞이지 않고 DB 포트가 외부에 열리지 않아야 한다.
- 관리자 최초 코드 명령이 실행 중 서버와 같은 DB를 사용해야 한다.
- 서버 연결을 끊어도 LCU와 기존 회원 명단 캐시로 대기를 만들 수 있어야 한다.
- 재실행·재설치·업데이트 동안 동일한 서버 주소·Windows 사용자·자료 폴더를 사용해야 한다.
- 인증 손상 전 백업하고, 복구 시 다른 회원을 만들지 않고 기존 회원의 새 코드를 사용해야 한다.

## 작업

- [x] `infra/home-server/`에 고정 이미지·상태 검사·Tunnel 비밀 파일을 사용하는 배포 설정을 준비한다.
- [x] 서버를 새로 빌드해 설정과 JAR만 담은 배포 ZIP을 만들고, 실제 로컬 컨테이너에서 시작·관리자 인증·개인 코드 발급을 확인한다.
- [x] 첫 설치판과 확인값을 별도 폴더에 보존하고 새 버전 설치판을 생성·검증한다. 실행 코드가 같고 버전만 다른 시험판임을 표시한다.
- [x] Windows 실기 절차와 결과 제출 양식을 작성하고, 코드·화면·서버 계약과 대조한다.
- [x] 기존 수집기 검사와 관련 서버 통합 검사, 형식·문서 검사를 실행한다. 실제 연동·가상 응답·Windows 미실행을 구분한 보고서를 남긴다.

이번 준비의 실행 증거와 실제 PC에서 남은 작업은 [보고서](../../validation/2026-10-26-collector-acceptance-preparation.md)에 정리했다. 위 체크는 준비 작업의 완료이며 Windows 실기 통과 표시가 아니다.

별도 기능 구현이나 자동 업데이트·진단 내보내기는 포함하지 않는다. 기존 미커밋 변경은 유지하며 커밋·게시·실제 Tunnel 연결은 이번 준비에 포함하지 않는다.
