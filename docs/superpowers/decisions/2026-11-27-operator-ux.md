# 운영자 화면과 공개 화면의 사용성 개선 결정

기록일: 2026-11-27. 운영자가 경기 정정·평가 기준·점수 재계산·변경 이력·코드와 인증 화면을 설명 없이도 이해하고, 되돌릴 수 없는 조작을 실수로 실행하지 않도록 화면을 바꿨다. 사용자가 여섯 가지를 직접 요청했고, 구현 담당자가 실제 사이트와 코드를 살펴 찾은 열두 가지를 사용자가 함께 진행하도록 승인했다.

현재 제품 기준의 정본은 [제품 명세](../../spec.md)이고 요청·응답은 [API 계약](../../contracts/api.md)이다. 이 문서는 당시 선택의 이유와 주체를 보존한다. 실행 결과와 한계는 [검증 보고서](../../validation/2026-11-27-operator-ux-report.md)에 둔다.

| 분류·주체 | 상태 | 지금 판단할 사항 |
| --- | --- | --- |
| 사용자 확정 · 사용자 | 아래 ‘사용자가 요청한 변경’ 여섯 가지 | 재승인 없음 |
| 사용자 확정 · 사용자 | 구현 담당자가 제안한 열두 가지를 2026-11-27 “전부 진행”으로 승인 | 재승인 없음 |
| 임시 선택 · 구현 담당자 | 아래 ‘구현 중 정한 세부 사항’ | 바꾸고 싶은 항목이 있으면 알림 |
| 범위 제외 · 사용자 | 메뉴 이동 때 페이지 전체를 다시 불러오는 구조의 변경 | 별도 작업으로 진행할지 |

## 사용자가 요청한 변경

| 화면 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 경기 정정 목록 | 날짜와 경기 번호만 적힌 버튼을 한 줄로 나열 | 공개 경기 기록과 같은 카드. 날짜·경기 시간·팀별 승패·챔피언·참가자 이름을 보여 주고 10경기씩 나눔 |
| 경기 안의 참가자 표 | 10명을 한 표에 두고 팀을 `100`·`200`으로 표시 | 블루팀·레드팀 표로 나누고 승패와 챔피언을 표시 |
| 원본 수치 보기 | 저장된 원본 자료를 펼쳐 표시 | 화면에서 제거 |
| 평가 기준 | ‘항목 내부 비율과 고정 표준화 상수’ 영역에서 내부 비율을 입력 | 영역 제거. 내부 비율은 최신 버전의 값을 이어받아 저장 |
| 재계산 작업 | 자료 버전·시도 횟수 같은 내부 값의 표 | 맨 위에 현재 상태와 마지막 계산 시각을 한 문장으로 표시. 표는 시작한 때·결과·적용한 평가 기준만 표시 |
| 변경 이력 | 영문 작업 이름, 내부 식별자, 항상 펼칠 수 있는 빈 `{}` | 한글 작업 이름, 참가자 이름·경기 날짜, 내용이 있을 때만 표시 |

빈 `{}`는 서버가 덧붙일 내용이 없는 작업에도 빈 값을 저장하고 화면이 이를 그대로 보여 주어 생긴 것이다. 서버의 기록 형식은 바꾸지 않았다.

## 구현 담당자가 제안해 승인받은 변경

1. 코드·인증: 모임 코드 재발급·삭제와 인증 폐기 앞에 확인 단계를 둔다. 지금 사용하는 브라우저를 표시하고 마지막 사용 시각을 보여 준다. 폐기되었거나 만료된 인증은 접어 둔다.
2. 경기 상세: 활약 점수를 참가자 이름 옆으로 옮기고, 표를 옆으로 넘겨도 이름 열이 보이게 한다.
3. 오류 안내: 운영자와 방문자가 만날 수 있는 오류 코드에 원인과 해결 방법을 한글로 안내한다.
4. 평가 기준: 합계가 100이 아닌 포지션을 강조하고 저장을 막는다. 새 버전 이름을 자동으로 제안하고, 버전 기록을 원본 자료 대신 가중치 표로 보여 준다.
5. 계산 중 깜박임: 같은 자료를 다시 받는 동안 기존 화면을 유지한다.
6. 글자 크기: 표 머리글과 운영자 메뉴의 글자를 키운다.
7. 저장 피드백: 참가자 저장 알림을 표시하고, 처리 중인 버튼을 다시 누를 수 없게 한다.
8. 반복 표시: 모든 항목에 똑같이 붙던 ‘팀 추천 대상’·‘정식 랭킹’·‘평가 완료’와 ‘5 VS 5 · 소환사의 협곡’을 없애고 예외인 상태만 표시한다.
9. 내부 값: 공개 화면의 경기 번호와 긴 패치 번호, 인증 식별자를 숨기거나 줄인다.
10. 이동 표시: 같은 사이트 안의 이동에 붙던 `↗`를 없애고 경기 카드 전체를 누를 수 있게 한다.
11. 팀 추천: ‘팀 합 차이’와 ‘기준값 50’의 뜻을 설명한다.
12. 참가자 추가: Riot ID 입력 형식을 안내한다.

## 이전 결정과의 관계

[밝은 화면 결정](2026-10-29-light-ui.md#구현-후-사용성-보완)은 공개 참가자 목록의 상태를 ‘팀 추천 대상/제외’로 통일했다. 이번에는 대상인 참가자의 표시를 없애고 제외된 참가자만 표시한다. 대부분의 참가자가 대상이어서 같은 표시가 반복되면 제외된 사람을 찾기 어렵다는 점이 이유이며, ‘팀 추천 제외’라는 용어와 과거 기록의 포함 범위는 그대로다.

원본 수치를 그대로 보존하도록 계약을 복원한 [D13](2026-10-22-overnight-decisions.md#d13--독립-리뷰의-json-계약-결함-수정)의 원칙은 유지한다. 서버는 원본을 계속 저장하고 운영자용 경기 상세 응답에도 계속 포함한다. 바뀐 것은 웹 화면이 이를 표시하지 않는다는 점이다.

평가 버전이 내부 비율·표준화 상수를 함께 보관하는 불변 버전이라는 [명세](../../spec.md#평가-버전과-한-묶음-공개)는 그대로다. 화면에서 내부 비율을 입력하던 기능만 없앴다.

## 구현 중 정한 세부 사항

문제마다 운영자가 이해하기 쉬운지, 서버 계약과 기존 시험을 얼마나 바꿔야 하는지, 과거 자료에도 적용되는지를 기준으로 비교했다.

| 문제 | 선택지 | 장점 | 단점·비용 | 판단 |
| --- | --- | --- | --- | --- |
| 경기 정정 목록의 페이지 나눔 | 화면이 전체 목록을 받아 10개씩 표시 | 서버 계약과 서버 시험을 바꾸지 않음 | 경기가 많아지면 한 번에 받는 자료가 커짐 | 채택 |
| | 서버 응답에 페이지 나눔 추가 | 경기가 많아도 응답 크기가 일정 | 계약·서버 코드·서버 시험 변경 | 채택하지 않음 |
| 원본 수치 | 화면에서만 제거하고 응답은 유지 | 계약 유지, 원본 정밀도를 확인하는 서버 시험 유지 | 쓰지 않는 자료를 화면이 계속 받음 | 채택 |
| | 응답에서도 제거 | 응답이 작아짐 | 계약 변경, 원본을 확인할 통로가 DB뿐 | 채택하지 않음 |
| 변경 이력의 쉬운 표현 | 화면이 작업 이름과 대상을 바꿔 표시 | 과거 기록에도 적용, 서버 변경 없음 | 새 작업 종류가 생기면 화면의 이름표도 고쳐야 하며, 모르는 작업은 영문 이름 그대로 표시 | 채택 |
| | 서버가 설명문을 함께 저장 | 화면이 단순해짐 | 과거 기록에는 적용되지 않음, 기록 형식 변경 | 채택하지 않음 |

경기 목록 응답이 느려지거나 경기 수가 화면에서 다루기 어려울 만큼 늘면 서버 페이지 나눔을 다시 검토한다. 그 밖의 세부 사항은 다음과 같다.

- 경기를 누르면 그 카드 안에서 정정 화면이 펼쳐진다. 목록 아래로 스크롤하지 않고 고른 경기 바로 밑에서 고칠 수 있게 하기 위해서다.
- 한 팀에 같은 포지션이 두 명이면 저장 전에 알리고 저장을 막는다. 서버도 같은 조건을 검사한다.
- 운영자 메뉴의 ‘재계산 작업’은 ‘점수 재계산’으로 이름을 바꿨다. 다시 시도 버튼은 최신 계산이 실패했을 때만 보인다.
- 새 평가 버전 이름은 `v`와 한국 날짜 여덟 자리(예: `v20261127`)로 제안하고, 같은 이름이 있으면 `-2`부터 번호를 붙인다. 운영자가 바꿀 수 있다.
- 주 포지션이나 부 포지션을 고르면 가능한 포지션에 자동으로 체크하고, 가능한 포지션에서 빼면 해당 주·부 포지션을 비운다. 서버가 요구하는 조건을 화면에서 미리 맞추기 위해서다.
- 운영자 브라우저 인증은 마지막 사용 후 7일이 지나면 서버가 받아들이지 않으므로 화면도 ‘만료됨’으로 표시한다. 기간의 원본은 [인증 코드](../../../apps/server/src/main/java/cw/auth/AuthService.java)다.
- 운영자 경기 정정 화면에는 문의·대조에 쓰도록 경기 번호를 작은 글자로 남겼다. 공개 화면에서는 표시하지 않는다.
- 챔피언 조건은 이름 전체가 맞거나, 입력한 글자가 한 챔피언에만 해당하면 적용한다. 숫자만 입력하면 이전처럼 챔피언 번호로 읽는다.

## 제외한 범위

메뉴나 운영자 탭을 누를 때마다 페이지 전체를 다시 불러오는 구조는 바꾸지 않았다. 화면 전환 방식을 바꿔야 해서 이번 변경과 성격이 다르며, 사용자가 승인한 범위에도 들어 있지 않다. 서버 코드와 API 응답도 바꾸지 않았다.
