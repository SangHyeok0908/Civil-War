# Windows 기기 등록·자료 보존·인증 복구 시험

첫 설치를 확인한 PC에서 실제 인증 파일과 대기 자료가 재실행·재설치·업데이트 뒤에도 남고, 인증 파일 손상 뒤 같은 회원의 재등록으로 전송을 마칠 수 있는지 확인한다. 사용자는 Windows 조작과 서버 배포를 맡고, 실행 결과를 전달하면 담당자가 검증 기록에 반영한다.

기록일: 2026-10-26. 편집·보완일: 2026-10-28. [시험 서버 배포](home-server.md)를 먼저 마친다. 설치 방법·저장 위치는 [설치 정본](collector-install.md), 상태·소유자·재시도 기준은 [오프라인 명세](../spec.md#오프라인-대기와-재시도)를 따른다. 절차를 제공한 사실은 시험 통과를 뜻하지 않는다.

## 준비와 중단 기준

- 내부 제거 프로그램을 포함한 배포 검사를 통과한 설치판을 자료 보존 시험의 기준판으로 사용한다. 제거 파일이 잘못된 과거 판은 [설치·복구 안내](collector-install.md#기존-제거-프로그램의-무결성-오류-복구)에 따라 재사용하지 않는다. 버전 간 업데이트를 시험할 때는 서로 다른 버전의 설치판·각 해시 목록을 준비하며, 같은 버전 재설치를 버전 간 업데이트로 세지 않는다. 저장 코드만 같은 버전 교체 시험은 구조 변경이나 자동 업데이트 시험과 구분한다.
- 이번 실행에서 선택·제외한 시험은 [상태 정본](../status.md#범위-제외와-미확인-사실)을 따른다. 업데이트·인증 손상 시험을 제외한 경우에는 아래 기존 인증 연결 복구 분기로 진행한다. 전체 절차를 제공한 사실을 제외한 시험의 재요구로 해석하지 않는다.
- 같은 Windows 사용자·롤 계정·시험 서버·회원·자료 폴더를 끝까지 사용한다. 실제 운영 계정과 DB를 시험 중 바꾸지 않는다.
- 기존에 완료한 적격 내전이 LCU에서 조회되고 참가자 10명이 시험 서버에 등록되어 있어야 대기를 만들 수 있다. 새 내전이나 시범 운영을 요구하지 않는다. 기존 경기가 없거나 지원 형식이 아니면 해당 시험을 **미실행**으로 남기고 이유를 전달한다.
- 각 절차가 실패하면 그 위치에서 중단하고 화면의 오류 코드와 관찰 결과만 기록한다. 자료 삭제·다른 회원 등록·백업 덮어쓰기로 성공처럼 만들지 않는다.

## 1. 첫 기기 등록과 재실행

수집기를 완전히 종료하고 PowerShell에서 실행한다. 서버 주소는 실제 값으로 바꾸고, 게임 설치 위치가 다르면 설치 안내대로 지정한다. **이후 모든 재실행도 같은 방식으로 한다.** 시작 메뉴로 실행하면 이 PowerShell의 서버 주소 설정이 적용되지 않을 수 있다.

```powershell
$env:CW_SERVER_ORIGIN = 'https://your-test-host.example'
$cwExe = Join-Path $env:LOCALAPPDATA 'Programs\Civil War Collector\Civil War Collector.exe'
& $cwExe
```

1. 롤 클라이언트에 로그인한 상태에서 본인에게 발급한 개인별 코드로 **기기 등록**을 누른다.
2. `기기 등록됨` 표시와 서버 오류가 없는지 확인한다. 자료 폴더의 `credential.bin` 존재를 확인하되 내용을 출력하지 않는다.
3. 수집기를 종료하고 같은 PowerShell에서 다시 실행한다. 코드를 다시 입력하지 않아도 기기 등록이 유지되고 서버 조회에 인증 오류가 없는지 확인한다. 이 확인을 실제 Windows 인증 암호화·복호화 결과로 기록한다.

```powershell
$cwData = Join-Path $env:APPDATA 'Civil War Collector'
Get-Item -LiteralPath (Join-Path $cwData 'collector.sqlite'), (Join-Path $cwData 'credential.bin') | Select-Object Name, Length
```

파일 존재만으로 복호화 성공을 판정하지 않는다. 온라인 재실행의 인증 상태·서버 응답과 함께 본다.

## 2. 전송·등록 대기 생성과 기준 백업

기존 설치판에서 `HISTORY_PAGINATION_STALLED`로 멈춰 대기 자료가 만들어지지 않았다면 [반복 페이지 수정 보고서](../validation/2026-10-28-history-pagination-report.md)의 수정 설치판으로 이 절차부터 다시 확인한다. 조회 범위 경고가 남더라도 실제 경기의 `전송 대기`·`등록 대기` 건수로 진행 여부를 판단한다. 적격 내전이 없으면 아래 보존 시험은 미실행으로 남기며, 자료를 만들기 위해 새 내전을 요구하지 않는다.

**이미 온라인 조회로 확인 대기가 생긴 경우:** 전송을 마친 같은 경기를 오프라인에서 다시 조회해도 새 전송 대기를 만들지 않는다. Tunnel을 끈 뒤에도 해당 확인 대기 경기와 목록이 남아 있다면 아래 3번부터 진행할 수 있다. 이 경로는 포지션·미전송 등록 요청의 보존을 확인하며, 경기 원본의 미전송 요청 보존은 별도 미확인으로 기록한다. 원본 전송 대기를 만들기 위해 DB·서버 자료를 삭제하거나 새 경기를 요구하지 않는다.

1. 기기 등록·회원 명단 동기화가 끝난 뒤 **서버 PC**에서 `docker compose stop cloudflared`를 실행한다. 롤 클라이언트와 인터넷 전체를 끄지 않는다.
2. **수집기 PC**에서 `과거 경기 조회`를 눌러 기존 적격 내전을 가져온다. 경기 한 건 이상의 `전송 대기`를 확인한다. 참가자 미등록·LCU 조회 실패는 대기 생성 성공이 아니다.
3. 시험할 경기의 양 팀 10명 포지션을 지정하고 내전 확인을 체크한 뒤 `내전 등록`을 누른다. 서버 연결이 끊긴 상태이므로 `등록 대기`가 되어야 한다. 가능하면 다른 한 경기는 등록을 누르지 않고 남겨 두되, 두 번째 경기를 필수로 새로 만들지 않는다.
4. 경기 식별자·건수·10명 포지션·대기 상태를 비공개 메모로 기록하고 수집기를 종료한다. **선택한 오프라인 보존 시험을 마칠 때까지 Tunnel을 끈 상태를 유지한다.** 제외한 시험은 수행하지 않고 연결 복구 분기로 진행한다.
5. 프로세스가 종료됐는지 확인한 뒤 폴더 전체를 로컬 백업한다. 폴더 안의 추가 SQLite 기록 파일도 함께 보존한다.

```powershell
if (Get-Process -Name 'Civil War Collector' -ErrorAction SilentlyContinue) { throw '수집기를 종료한 뒤 다시 실행하세요.' }
$cwBackupRoot = Join-Path $env:LOCALAPPDATA ('CivilWarAcceptanceBackups\' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $cwBackupRoot | Out-Null
Copy-Item -LiteralPath $cwData -Destination (Join-Path $cwBackupRoot 'baseline') -Recurse
$cwCredentialHash = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $cwData 'credential.bin')).Hash
```

백업은 이번 PC에만 보관한다. 인증·식별자·경기 원본이 있으므로 폴더 전체나 DB를 공개 결과로 보내지 않는다.

## 3. 재실행·재설치·새 버전 업데이트

각 행을 순서대로 수행하고 완료할 때마다 종료한다. 앱을 열었을 때 2절의 경기·포지션·대기 상태와 `기기 등록됨`이 유지되는지 확인한다. 서버 오류는 Tunnel을 의도적으로 끈 결과와 구분한다.

| 시험 | 직접 할 일 | 통과 기준 |
| --- | --- | --- |
| 재실행 | 같은 PowerShell에서 수집기를 다시 실행 | 새 코드 입력 없이 기존 인증을 읽고, 기존 요청·포지션이 남음 |
| 제거 후 재설치 | Windows 설정에서 수집기를 제거하고 **현재 시험의 정상 기준판**으로 다시 설치 | 사용자 자료 폴더가 남고, 재등록 없이 기존 자료를 읽음 |
| 다른 버전으로 업데이트 | 종료한 뒤 **새 버전** 설치 파일 실행. 이전 버전을 먼저 제거하지 않음 | 실행 파일 버전이 새 값으로 바뀌고 기존 인증·자료·요청을 읽음 |

```powershell
# 새 설치 후 실행 파일 버전 확인
(Get-Item -LiteralPath $cwExe).VersionInfo | Select-Object ProductName, FileVersion
# 4절의 의도적 손상 전에 인증 파일이 유지됐는지 확인
(Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $cwData 'credential.bin')).Hash -eq $cwCredentialHash
```

경기 DB는 실행 중 재시도 횟수·시각이 바뀔 수 있으므로 파일 전체 해시의 동일성을 요구하지 않는다. 실제 화면의 경기·포지션·대기 내용과 인증 복호화로 판정한다. 백업을 복원한 뒤 나온 자료를 설치기의 보존 성공으로 기록하지 않는다. 같은 버전 재설치를 버전 간 업데이트로 세지 않는다.

### 제거 후 같은 판 재설치의 상세 순서

1. 현재 사용 중인 정상 기준판의 설치 실행 파일을 준비한다. 수집기를 종료하고 `collector.sqlite`·`credential.bin`과 기준 백업의 존재를 확인한다. 제거 전 인증 파일 해시를 PowerShell 변수에 보관한다. 기존에 기록한 기준 해시가 있다면 함께 대조한다. 이 비교용으로 해시를 기록하는 일은 백업을 대신하지 않는다.
2. Tunnel을 계속 끈 상태에서 Windows **설정 → 앱 → 설치된 앱** 또는 **앱 및 기능**의 `Civil War Collector`를 제거한다. 제거 창을 끝까지 마친다. 현재 설치 설정은 사용자 자료를 보존한다. 자료 삭제 선택지가 보이면 선택하지 않는다.
3. 다시 설치하기 전에 원래 자료 폴더의 두 파일이 남았는지와 인증 파일 해시가 제거 전 값과 같은지 확인한다. 이때 새 폴더를 만들거나 백업을 복원하지 않는다. 파일 누락·해시 불일치·제거 오류는 해당 결과를 기록하고 멈춘다.
4. 준비한 같은 판의 `Civil-War-Collector-Setup-<버전>-x64.exe`로 설치한다. 과거 제거 프로그램 복구 도구는 다시 실행하지 않는다. 설치 뒤 수집기를 열기 전에 파일 존재·인증 해시와 실행 파일 버전을 확인한다.
5. 앞서 사용한 PowerShell에서 같은 서버 주소로 실행한다. 새 등록 코드 없이 인증이 유지되고 기준 경기·포지션·등록 대기·확인 대기가 남는지 확인한다. 이때 과거 경기 조회나 서버 대기 불러오기는 누르지 않는다. 서버가 끊긴 상태에서 기존 자료만으로 확인하며, 끝나면 수집기를 종료하고 Tunnel을 계속 꺼 둔다.

앱을 같은 판으로 다시 설치하는 이 절차에는 버전 변경이나 인증 손상을 포함하지 않는다. 제거·설치 중 오류가 나거나 실행 뒤 자료가 다르면, 수동 삭제·인증 재발급·백업 복원 전에 실패 위치를 전달한다. 백업으로 되돌리는 복구는 자료 보존 시험의 통과와 구분한다.

### 기존 인증을 유지한 채 연결 복구

업데이트·인증 손상 시험을 생략하고 현재 등록 요청을 처리할 때 사용한다. 범위 변경의 주체·이유·검증 한계는 [D30](../superpowers/decisions/2026-10-22-overnight-decisions.md#d30--2026-10-28-업데이트인증-손상-시험-제외와-기존-요청-처리)에 기록한다. 인증 폐기·새 코드 발급·재등록은 하지 않는다.

1. 서버 배포 폴더에서 `docker compose start cloudflared`를 실행하고 기존 HTTPS 주소로 서버가 열리는지 확인한다.
2. 수집기를 같은 Windows 사용자·롤 계정·서버 설정으로 실행한다. 기존 인증에 묶인 등록 요청은 연결 복구 후 자동 재시도된다. 이미 등록 완료면 재개 버튼을 누를 필요가 없다.
3. `본인 대기 요청 재개`를 한 번 눌러 본인 확인과 전송 시도를 요청할 수도 있다. 기존 네트워크 오류의 재시도 예약 시각은 이 버튼으로 초기화되지 않으므로 즉시 완료를 요구하지 않는다. [재시도 간격](../spec.md#오프라인-대기와-재시도)이 지나도 처리되지 않으면 상태·오류·경과 시간을 기록한다.
4. 등록 요청한 경기만 등록 완료이고 다른 확인 대기 경기는 그대로인지 확인한다. 서버 웹에서도 대상 경기가 한 번만 등록됐고 양 팀 포지션이 일치하는지 대조한다.
5. 수집기를 종료·재실행해 기존 인증과 최종 상태가 유지되는지 확인한다. 이 분기에서는 다음 4절의 인증 손상 명령을 실행하지 않는다.

## 4. 인증 파일 손상과 같은 회원의 재등록

대기 요청이 남아 있고 Tunnel이 계속 중단된 상태에서 시작한다. 2절 백업이 실제로 존재하는지 확인하고, 수집기를 종료한 상태에서 인증 파일만 시험용 잘못된 값으로 바꾼다. 이 블록은 **의도적으로 현재 인증 파일을 손상시킨다.**

```powershell
if (Get-Process -Name 'Civil War Collector' -ErrorAction SilentlyContinue) { throw '수집기를 먼저 종료하세요.' }
if (-not (Test-Path -LiteralPath (Join-Path $cwBackupRoot 'baseline\credential.bin'))) { throw '기준 인증 백업이 없어 중단합니다.' }
Copy-Item -LiteralPath (Join-Path $cwData 'credential.bin') -Destination (Join-Path $cwBackupRoot 'credential-before-corruption.bin')
[IO.File]::WriteAllBytes((Join-Path $cwData 'credential.bin'), [byte[]](67, 87, 45, 98, 97, 100))
& $cwExe
```

1. `보호된 인증 정보를 읽지 못했습니다. 기기를 다시 등록하세요.` 안내가 나오는지 확인한다. 읽을 수 있는 인증이 없으면 경기 목록이 숨겨질 수 있다. 이 상태만으로 DB 소실이라고 판정하지 않는다.
2. 수집기를 다시 종료한다. **서버 PC**에서 `docker compose start cloudflared`를 실행한다. 수집기를 닫아 둔 채 관리자 화면에서 이 시험 기기의 기존 인증을 폐기하고 **동일 회원**의 새 수집자 코드를 발급한다. 다른 기기의 인증을 폐기하지 않는다.
3. 수집기를 같은 설정으로 실행하고 새 코드로 기기를 등록한다. `기기 등록됨`으로 바뀌고 기존 경기·포지션이 다시 보이는지 확인한다. 손상된 예전 파일을 백업에서 복원하지 않는다.
4. **본인 대기 요청 재개**를 누른다. 새 인증을 발급받는 것과 과거 요청의 재개는 별도 동작이다. 재개 전까지 이전 인증에 묶인 요청이 임의로 전송되지 않는지 확인한다.
5. 재시도 간격이 남아 있으면 기다린다. 네트워크가 정상인데도 [재시도 기준](../spec.md#오프라인-대기와-재시도)의 최대 간격이 지나도록 해결되지 않으면 오류 코드·경과 시간을 기록한다. 전송 성공 확인 전에 재개 버튼을 반복 누르거나 DB를 편집하지 않는다.
6. `내전 등록`을 누른 경기는 `등록 완료`, 누르지 않은 경기가 있다면 `확인 대기`인지 확인한다. 서버 웹에서도 대상 경기 한 건이 한 번만 등록되고 포지션이 일치하는지 확인한다. 등록되지 않은 경기를 성공 표시만 보고 완료로 세지 않는다.
7. 수집기를 한 번 더 종료·실행해 새 인증과 최종 상태가 유지되는지 확인한다.

기존 인증 폐기는 손상된 로컬 파일을 고치는 작업과 다르다. 새 인증 발급만으로 예전 서버 토큰이 자동 폐기되지는 않으므로, 폐기 대상을 확인하고 별도로 처리한다.
