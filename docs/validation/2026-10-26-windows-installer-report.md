# Windows 수집기 설치 파일 생성 검증

기록일·편집일: 2026-10-26. 사용자는 개발 도구 없이 설치할 실행 파일을 받아 다음 자료 보존 시험의 기준 버전으로 사용할 수 있다. 아래 빌드 기록은 설치 파일 생성 시점의 결과이며, 이후 같은 날 전달받은 실제 Windows 기본 설치 결과는 [사용자 확인](#후속-windows-기본-설치-사용자-확인)에 별도로 덧붙였다. 최신 진행 상태는 [정본](../status.md), 사용법은 [설치 안내](../runbooks/collector-install.md)에 있다.

## 환경과 산출물

macOS arm64, Node.js 24.22.1·pnpm 11.5.0에서 Windows x64용 NSIS 설치 파일을 교차 생성했다. Electron 45.0.0과 electron-builder 26.18.0을 사용했다. 이 값은 이번 실행의 측정 기록이며 이후 빌드 설정의 복사본으로 관리하지 않는다.

산출물은 `dist/collector/`의 설치 실행 파일·해시 목록·배포 메타데이터다. 생성 후 실제 파일의 크기·SHA-256, 앱 묶음의 파일 목록·버전, Windows 실행 파일의 제품명과 CPU 형식을 [공개 감사 결과](assets/windows-installer-audit.json)에 기록했다. 사용자 자료와 원본 계정 정보는 감사 파일에 없다. 실행 파일 자체는 Git에 넣지 않으며 재생성법은 설치 안내를 따른다.

## 실행과 확인 결과

| 검사 | 결과 | 확인한 범위 |
| --- | --- | --- |
| `pnpm install --frozen-lockfile` | 통과 | 고정된 설치 도구·의존성 준비. 사용하지 않는 Squirrel 설치기의 후처리는 실행하지 않도록 명시 |
| `pnpm test` | 7개 파일의 단위 테스트 60개 통과 | 기존 수집·계약·대기 처리. 실제 Windows 인증 보호 시험과 구분 |
| `pnpm test:collector-release` | 배포 테스트 5개 통과 | 설치 전용 빌드의 시험 자료 제외, 실제 해시·크기 생성과 검증, 변경·누락·다른 버전 파일·경로 이탈 거절 |
| `pnpm typecheck` | 통과 | TypeScript 타입 검사 |
| `pnpm package:collector` | 통과 | 개발용 출력과 분리한 설치용 빌드와 서명 없는 설치 실행 파일 생성 |
| `pnpm verify:collector-release` | 통과 | 최종 실행 파일과 두 확인 파일의 일치 |
| 묶음·실행 파일 직접 검사 | 통과 | app.asar는 파일 6개·디렉터리 3개. 개발 의존성·시험 경기 응답 표식 미포함, 앱 진입점·화면·내장 SQLite 호출 포함. 실행 파일은 x86-64이며 제품명·버전 정보 반영. React·React DOM 라이선스 2개를 별도 리소스로 보존 |
| `pnpm test:e2e` | Electron 시나리오 7개 통과 | macOS에서 실제 Electron·파일 SQLite, 게임·서버는 가상 응답. 별도 배포 파일의 Windows 실행 검사가 아님 |
| `pnpm format:check`·`git diff --check` | 통과 | 변경한 코드·설정의 형식과 공백 오류 |
| `pnpm test:docs`·`pnpm docs:check` | 통과 | 문서 검사기 테스트 66개와 등록·링크·안내표·중복 검사 |

배포 테스트는 빈 구현에서 4개가 실패하는 것을 확인한 뒤 구현했다. 별도 검토에서 기존 빌드가 시험 응답을 실행 파일 안에 포함하는 문제를 발견했다. 설치 전용 출력·컴파일 분기를 추가하는 회귀 검사가 먼저 실패했고, 수정 후 5개 모두 통과했다. 최종 app.asar 내부를 다시 읽어 해당 응답·시험 서비스가 제거된 결과를 확인했다.

처음 Electron 화면 검사는 샌드박스에서 프로세스 시작이 거절되어 7개 모두 실패했다. 앱 실행 권한이 있는 환경에서 다시 실행해 7개가 통과했다. 최초 의존성 추가 때 사용하지 않는 후처리 스크립트의 미선택 오류도 발생했고, 해당 스크립트를 실행하지 않는 설정을 명시한 뒤 고정 잠금 파일 설치가 통과했다.

## 설치 파일 생성 시점의 미확인 사항

- 실제 Windows에서 설치 파일 실행·앱 제거·이전 버전에서의 업데이트와 사용자 자료 보존
- 실제 Windows 보호 저장소의 암호화·복호화·손상 후 재등록 복구
- 실제 게임 연결·운영 서버 연결·서명 없는 파일에 대한 Windows 경고
- 변경한 Windows CI(지속적 통합 검사)의 원격 실행. 이번 결과는 로컬 실행이며 자동 게시·업로드는 수행하지 않음

현재 파일을 반복 설치하는 것과 서로 다른 버전 사이의 업데이트 시험은 구분한다. 기존 조회 조건 비교와 새 내전 시범 운영을 완료 조건으로 다시 추가하지 않는다.

## 후속 Windows 기본 설치 사용자 확인

확인 결과 수신일·편집일: 2026-10-26. 사용자가 이 대화에서 Windows 11 x64 PC의 실행 결과를 직접 전달했다. 앞의 macOS 빌드 검사와 별개인 사용자 실기 확인이며, 담당자가 해당 PC를 직접 조작하거나 화면·로그를 독립 확인한 기록은 아니다.

대상은 앞에서 전달한 첫 설치판 `0.2.0-provisional`이다. 사용자는 제공한 확인값과 설치 파일의 해시가 일치했다고 보고했다. 대상 파일의 상세 정보는 [생성 당시 감사 결과](assets/windows-installer-audit.json)에 있다. 그 파일의 `actualWindowsInstallationTested: false`는 당시 macOS 검사 범위를 보존하는 값이며 이번 사용자 확인으로 소급 수정하지 않는다.

| 사용자 보고 항목 | 전달받은 결과 | 해석 범위 |
| --- | --- | --- |
| 실행 환경 | Windows 11, x64 | 세부 OS 빌드 번호는 제공되지 않음 |
| 파일 해시 | 일치 | 전달한 설치 파일의 확인값과 대조했다고 보고 |
| 설치 | 성공 | 첫 설치 확인. 제거 후 재설치·다른 버전 업데이트는 별도 |
| 설치 시 경고 | 처음 setup 실행 시 확인되지 않은 프로그램이라 안전하지 않다는 경고 | 사용자의 설명을 기록. 경고 화면·정확한 제품명·전문은 제공되지 않아 특정 Windows 보호 기능의 경고로 단정하지 않음 |
| 수집기 화면 | 열림 | 설치판의 기본 실행 확인 |
| 롤 로그인 후 계정 인식 | 성공 | 실제 클라이언트 계정 인식 확인. 경기 목록·상세 수집이나 서버 인증 성공을 뜻하지 않음 |
| 수집기 종료 후 재실행 | 정상 | 동일 앱 재실행 확인. PC 재부팅·다른 Windows 사용자 시험은 아님 |
| `collector.sqlite` | 존재 | 로컬 저장 파일 생성 확인. 경기·대기 자료의 내용과 업데이트 보존 검증은 아님 |

기기 등록·인증 파일 생성과 복호화, 전송·등록 대기 자료의 보존, 앱 제거 후 재설치, 새 버전 업데이트와 서버 연결은 이번 보고에 포함되지 않았다. 다음 보존·인증 시험에는 연결할 시험 서버·등록 코드·보관할 시험 자료를 준비해야 한다. 새로운 내전이나 제외한 시범 운영을 요구하지 않는다.
