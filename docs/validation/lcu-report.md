## 2. 실행 순서와 증거

1. 첫 정상 내전에서는 경기 중 도구를 실행하지 않는다. 경기 종료 후 처음 실행하여 명시적으로 조회한다.
2. 다른 실행에서는 도구를 미리 실행하고 대기시킨다. 조회 명령 전 경기 기록 요청이 0건인지 확인한 뒤 명시적으로 조회한다.
3. 같은 경기를 두 실행 조건에서 비교한다. 종료 직후 조회와 필요 시 약 1분·5분·15분 뒤 재조회를 각각 기록한다. 자동 반복 조회로 대체하지 않는다.
4. 클라이언트를 재시작하고 현재 연결 정보를 다시 읽어 같은 경기를 재조회한다.
5. 최소 두 실제 경기에서 응답 구조를 확인한다. 같은 경기 참가자 두 명의 PC에서 경기 키와 핵심 기록을 대조한다.
6. 결과 화면과 원본 JSON을 대조하여 [필드 맵](lcu-field-map.md)을 채운다. 더 오래된 경기의 조회 범위·페이지 제한과 솔로랭크 참고 자료도 확인한다.

15분은 관찰 창이며 제품의 조회 보장 기한이 아니다. 정상적으로 진행하는 경기에서 검증하며 고의 탈주나 비정상 경기를 만들지 않는다.

## 4. 필드 맵·가명화 fixture

- 필드 맵: [lcu-field-map.md](lcu-field-map.md) — G1–G3의 실제 JSON 경로·타입·존재 여부를 기록했다. 화면과 의미 대조는 대기 중이다.
- 실제 원본: 사용자 제공 `lcu-probe-kit.zip`, `lcu-probe-kit-1.0.1.zip`의 `.private/lcu/`에 보관. 두 번째 압축본에서 경기 목록과 상세 3건 확보. 친구 본문과 실명 대응표는 미확보·미생성.
- 검증된 가명화 fixture: 없음. 실측 전 `fixtures/lcu/verified/`에 예시나 가상 응답을 넣지 않는다.
- 가명화 검증: 미실행. 여러 경기에서 같은 계정 가명을 유지하고 인증 정보·실제 식별자의 잔존 여부를 검사한다.

## 5. Gate 판정과 다음 단계

**현재 HOLD 사유:** 과거 사용자 설정 경기 3건의 목록·상세와 기본 통계 필드는 확보했다. 화면 통계 대조, 동일 경기 두 PC 비교, 재시작 전후 안정성, 종료 직후 반영 지연과 솔로랭크 초기 포지션 참고 경로가 남아 있다. 친구 목록 조회는 이 판정의 조건이 아니다. 가상 서버 테스트나 일부 항목 PASS를 전체 실기 PASS로 계산하지 않는다.

핵심 수집·식별 요구를 실측으로 충족하고 평가·초기 포지션 참고 기능의 구현 경로가 확정된 경우에만 PASS로 변경한다. 두 번째 PC 대조를 생략한 채 전체 PASS로 표시하지 않는다. 필수 지표 변경이 필요하면 사용자 결정과 기획서 반영을 먼저 기록한다. 타임라인 누락만으로 HOLD 처리하지 않는다.

본 서비스 T01의 데이터 계약 확정은 이 gate 통과 이후 진행한다.

## 6. 도구 준비 검증 — 실제 LCU 결과 아님

- 실행 환경: macOS arm64, Node.js 24.22.1. 공식 배포 파일의 SHA-256 확인 후 임시 런타임으로 실행.
- 범위: 루프백 HTTPS 가상 서버, 합성 lockfile과 응답만 사용. 실제 계정·경기·클라이언트 미사용.
- 확인: 연결 대상·경로 제한, 명령 전 요청 0건, lockfile 갱신, 0/누락 보존, 큰 경기 ID 보존, HTTP/네트워크 오류 구분, 인증 정보 포함 응답 차단, 가명 일관성, 비공개 출력 경로.
- 명령: `node --test tools/lcu-probe/probe.test.mjs`; 최종 전체 검증 `node --test` → **18/18 PASS**.
- 코드 리뷰: 부분 응답 중단·타임아웃 시 이미 받은 HTTP 상태가 유실되는 문제를 실패 테스트로 재현하고 수정. 두 회귀 테스트 포함 전체 통과.
- Windows 실행 절차: [README](../../tools/lcu-probe/README.md).

## 7. 첫 Windows 결과에 따른 수정과 재검증

- 압축 무결성 정상, 6개 session·5개 capture·9개 요청, 응답 파일 8개와 manifest 참조가 일치한다. HTTP 200은 5건(저장 성공 4건, 친구 본문 차단 1건), 400은 2건, 404는 2건이다.
- 기본·PUUID 경기 목록은 `beginIndex`를 거부했다. [클라이언트 Swagger 기반 문서](https://lcu.kebs.dev/)의 `begIndex`와 대조하여 1.0.1의 요청 생성과 허용 경로를 수정했다. 페이지 끝 인덱스의 실제 의미는 여전히 실측 대상이다.
- 1.0.0 친구 차단은 HTTP 오류가 아니며 당시 원문·진단이 없어 원인 필드를 확정하지 못했다. 그래서 1.0.1에 `sensitivity.rules`, `keyCategories`, `recognizedFields`의 고정 분류 기록을 추가했다. 임의 키·값·JSON 경로를 저장하거나 차단을 해제하지 않았다.
- `REPLACE_WITH_PUUID`는 이제 요청 전에 거절한다. 기본 history가 실제 목록 ID로 상세를 수집하며, README의 선택 조회도 manifest에서 실제 ID를 읽도록 바꿨다.
- 수정 전 회귀 테스트: 잘못된 인자·진단 누락·예시 PUUID 허용을 포함한 6개 실패 확인. 수정 후 Node.js 24.22.1/macOS arm64에서 `node --test` → **22/22 PASS**.
- 당시 다음 실측은 1.0.1의 history(count=3), friends였다. 그 실행 결과는 아래 8절에 기록한다.

## 8. 1.0.1 Windows 재검증 결과와 친구 오탐 보완

아래 친구 조회·보완 내용은 범위 정정 이전의 실행 이력이다. 1.0.2 Windows 친구 재조회는 더 이상 요청하지 않으며, 원문 미확인은 후속 내전·솔로랭크 검증을 막지 않는다.

- 원본: `lcu-probe-kit-1.0.1.zip`. 압축 무결성 정상, 도구 파일은 1.0.1 작업본과 일치한다. 2개 session·2개 capture·총 7개 요청이며 history 6개 응답 JSON과 친구 차단 manifest를 확인했다.
- 실제 history의 6개 요청(버전·현재 계정·목록·상세 3건)은 모두 HTTP 200, errors=0이다. `begIndex` 수정의 Windows 효과를 확인했다. `begIndex=0&endIndex=2`에 3건과 `gameIndexBegin=0`, `gameIndexEnd=2`, `gameCount=3`이 반환됐다. 다른 범위는 아직 미확인이다.
- G1/G2/G3는 모두 `CUSTOM_GAME`, `CLASSIC`, mapId=11, queueId=3130, platformId=KR, endOfGameResult=`GameComplete`다. 경기 생성 시각은 KST 2026-10-10 02:04:04.988 / 01:03:02.939 / 00:09:50.565이며 gameDuration은 1942 / 3062 / 2003이다. 수집일 기준 약 12일 전 자료다. 새 내전을 하지 않았어도 기존 사용자 설정 경기가 조회됨을 확인했다.
- 각 경기 고유 PUUID 10개, 팀 5+5, 참가자·식별 배열 연결과 팀·개인 승패 일치, 목록·상세 경기 ID 일치를 확인했다. 수집자 PUUID도 세 경기 모두 참가자에 포함된다. 계정값은 문서에 출력하지 않는다.
- 요구 기본 통계는 참가자 행 30개 모두 존재하고 null이 없다. 오브젝트 피해는 0인 행 1개/양수 29개, 포탑 피해는 0인 행 4개/양수 26개다. 필드 존재 확인과 결과 화면의 의미·수치 검증은 구분한다.
- 친구 응답은 HTTP 200이며 `rules=[sensitive-key]`, `keyCategories=[token]`, `recognizedFields=[challengeTokensSelected]`다. **이 필드가 키 이름 검사에 걸렸다는 사실은 확인됐지만, 다른 token 키의 동반 여부와 값·정확한 위치는 본문이 없어 미확인이다.** 현재 인증값 일치나 Authorization/Bearer 표식은 이 검사에서 검출되지 않았다.
- [Riot 도전과제 설명](https://www.leagueoflegends.com/en-au/news/game-updates/challenges-walkthrough/)은 최대 3개의 표시용 토큰을 설명하며, [LCU 라이브러리의 직접 타입 정의](https://github.com/Its-Haze/lcu-gopher/blob/master/types.go)는 친구 객체의 `lol.challengeTokensSelected`를 문자열로 정의한다. 이는 인증 token과 구별할 근거다. 실제 사용자 응답의 값 형식을 확보한 것은 아니다.
- 1.0.2는 `/lol-chat/v1/friends`의 배열 요소 `lol.challengeTokensSelected`에 한해 빈 문자열 또는 최대 3개의 쉼표 구분 숫자 ID(각 1~10자리)를 키 이름 차단에서 제외한다. 해당 값도 현재 인증값 일치 검사를 거치며, 다른 위치·형식·인증 키·token 이름 필드는 계속 차단한다. 원문 JSON을 변형하거나 데이터를 버리지 않는다.
- 합성 응답의 오탐을 실패 테스트로 재현한 뒤 수정했다. 독립 검토에서 찾은 중복 JSON 키의 검사 우회도 재현하고 `DUPLICATE_JSON_KEYS`로 본문 저장 전에 차단했다. 이스케이프 동등 키·중복 부모 객체를 포함한 Node.js 24.22.1/macOS arm64 전체 테스트 **26/26 PASS**, 수정 재검토에서 추가 지적 없음. 사용자 친구 응답의 실제 형식·다른 차단 키 여부는 미확인으로 남기며 추가 조회하지 않는다.
