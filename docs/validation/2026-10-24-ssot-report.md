## 오류 탐지와 내용 대조

초기에는 구현이 없는 검사기 테스트가 실패했다. 이후 일반 Markdown 제목 검사로 JSON Schema의 정의 링크를 잘못 거절한 통합 오류를 발견해 JSON Pointer(구조 안의 항목 경로) 존재 여부를 검사하도록 수정했다. 코드 들여쓰기·줄바꿈·언어 표시가 달라도 같은 본문을 찾는 사례와, 과거 기록이 현재 정본 대신 안내 문서를 가리키는 사례도 실패를 먼저 확인하고 수정했다.

11개 임시 변이에서 등록·정본·주제·앵커·링크·과거 기록·중복·경로 검사를 비활성화했을 때 테스트가 이를 탐지하는 것도 확인했다. 변이는 임시 사본에서만 수행했다. 실제 저장소 오류를 전부 재현했다는 뜻은 아니다.

내용 대조에서는 포지션 가중치·정규화 상수·누적 보정·동점 처리·팀 후보 기준, 인증·등록·취소·대기열 보존, API와 원본 매핑의 예외가 새 정본에 남았는지 확인했다. 인증·요청 제한의 수치는 계약에, 평가·팀 선택의 수치는 제품 명세에 두었다. 개발 안내의 설명문에 남은 설정 기본값도 원본 링크로 바꾸고 실행 예시만 예시임을 표시했다. 현재 문서의 상태 표현은 상태 문서와 대조했고 과거 기록은 당시 판단으로 읽히도록 표시했다.

독립 검토에서 대소문자가 섞인 Markdown 확장자가 Git 탐색에서 빠지는 문제도 발견했다. `.MD`·`.Md`의 등록·링크 오류가 실제 실패하는 테스트를 먼저 추가하고, Git 경로 탐색을 대소문자 구분 없이 수행하도록 고쳤다. 또한 정본으로 파일 대신 디렉터리를 등록해도 통과하던 사례를 실패 테스트로 재현한 뒤 파일만 허용하도록 고쳤다.

## 제한과 남은 확인

- 당시 자동 중복 검사는 긴 동일 블록의 문자열 비교였고 과거 기록은 본문 중복 검사에서 제외했다. 표현이 다른 의미 중복과 판단의 타당성·언어별 공백 의미는 판정하지 못했다. 현재 검사 범위·실행법은 [문서 검사](../development/setup.md#문서-검사)에서 확인한다.
- 내부 링크는 저장소의 Markdown 문법을 처리하는 검사기로 확인했다. 외부 웹 주소의 실제 접속·변경은 검사하지 않는다. 조건부 근거의 원본 내용이나 재현 가능성을 이 작업에서 다시 검증하지 않았다.
- CI 작업은 추가했지만 이 작업의 GitHub 호스팅 실행 결과는 없다. 로컬 명령 통과를 호스팅 성공으로 표시하지 않는다.
- 2026-10-24 대조에서는 [스키마](../contracts/stage3.schema.json#/$defs/RoleReferenceSample)가 evidence의 추가 필드를 금지하고 teamPosition을 요구하지만, 당시 [가져오기 코드](../../apps/server/src/main/java/cw/members/MemberReferenceImporter.java)는 추가 키를 별도로 막지 않고 role이 null이면 teamPosition 검사를 건너뛰는 차이를 확인했다. 이 문서 작업에서 제품 검증기를 변경하지 않았고 완전 일치를 주장하지 않았다. 현재 요청 기준은 [가져오기 계약](../contracts/api.md#공식-기록-참고-자료-가져오기)으로 연결한다.
