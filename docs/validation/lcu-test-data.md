## 확인한 사항

- 현재 계정·목록·경기 상세 3건을 기존 `redact.mjs`의 한 실행에 전달해 가명 일관성을 유지했다. 비교표의 P01~P10은 가명 PUUID에 연결한 읽기용 이름이다.
- 필수 숫자 통계 22개 × 30행 = **660개**가 원본과 일치한다. 가명화 JSON에 남긴 비식별 스칼라 1,639개도 원본과 타입·값이 일치한다. 팀·개인 승패, 5+5 팀, 참가자 번호 연결을 확인했다.
- 경기별 가명 계정은 10개이고 세 경기 전체의 고유 계정도 10개다. 팀·참가자 번호가 달라져도 같은 계정의 가명을 유지한다.
- 목록 응답은 경기당 수집자 1명의 통계만 포함하며 해당 통계는 상세와 일치한다. 전체 10명 비교는 상세 JSON으로 수행한다.
- 원본에 있는 실제 PUUID·계정/소환사/경기 ID·이름·태그의 잔존 검사를 통과했다. 인증 표식과 원본 경로가 없고 실계정 대응표가 묶음에서 제외된 것을 확인했다. 가명화 결과이지 완전한 익명성을 보장하는 자료라는 뜻은 아니다.
- 필수 통계에 누락·null이 없으며 실제 0은 보존했다. 오브젝트 피해 0은 1행, 포탑 피해 0은 4행, item0~5의 0은 7개다. 시야 점수 0의 실제 사례는 없다.
- 생성된 Markdown의 90개 표 행을 다시 읽어 기대값과 대조했다. 30개 참가자 행마다 통계·CS/골드/시야·아이템의 세 표를 제공한다.
- Node.js 24.22.1에서 이번 작업에 해당하는 오프라인 테스트 **3/3 PASS**. 전체 26개 테스트는 샌드박스에서 로컬 HTTPS 포트 열기가 차단되어 5개 통과·21개 `listen EPERM`이었고, 권한 확장 재실행은 사용자 턴 전환으로 중단됐다. 전체 테스트 통과로 기록하지 않는다. 수집 도구 코드는 수정하지 않았다.

## 해석과 사용 범위

- `csCandidateSum`은 `totalMinionsKilled + neutralMinionsKilled`의 계산값이다. 아군·적 정글 하위 필드를 다시 더하지 않는다. G1의 10명 모두 화면 CS와 일치하며 G2·G3 추가 화면 대조는 사용자 결정으로 생략한다.
- 챔피언 대상 피해·받은 피해·오브젝트 피해·포탑 피해를 분리했다. 오브젝트와 포탑 피해는 중복 포함 여부가 미확인이므로 합산하지 않는다.
- 경기 상세의 `accountId`와 `currentAccountId`는 모두 0이었다. 여러 참가자가 공유하는 자리표시 값이므로 계정 연결에 사용하지 않는다. 이름 대신 PUUID 가명을 사용했다.
- 실제 정수 식별자는 가명 문자열로 바뀐다. 원본 숫자 ID 파싱에는 비공개 원본이 필요하다. 다른 PC의 경기 키 대조는 사용자 결정으로 생략한다.
- 기존 보수적 가명화 정책에 따라 경기 생성 시각·자유 문자열·허용되지 않은 필드는 제거했다. `timeline.role`의 `CARRY`/`SUPPORT`도 기존 허용 목록에 없어 제거됐으며, 이 후보를 완전한 역할 분석 자료로 간주하지 않는다. 요구된 비교 통계는 모두 보존했다.
- 결과 화면 대조는 **대표 경기 G1 숫자 통계·슬롯 점유 일치, G2·G3 추가 검증 생략**이다. 두 경기의 추가 화면은 gate 조건에서 제외하며 기존 JSON 검사 결과는 유지한다. G1은 화면의 1번 팀이 teamId=200(승), 2번 팀이 teamId=100(패)에 대응했다. 이를 모든 경기의 고정 대응으로 일반화하지 않는다. 아이템의 정확한 ID는 작은 아이콘만으로 확정하지 않았다. 클라이언트 재시작 후 같은 경기 재조회와 다른 PC 경기 식별자 비교는 **사용자 결정으로 생략**하고 gate 보류 조건에서 제외했다. 두 항목을 검증 PASS로 기록하지 않는다. 나머지 검증 항목이 남아 있어 전체 gate는 HOLD다.

## 비공개 원본과 재현 자료

원본은 `.private/lcu/source-h2-20261021/`, 원본과 가명의 대응표는 `.private/lcu/redacted-h2-20261021/aliases.private.json`에 별도 보관했다. 원본 파일 해시는 `source.private.json`에 있다. 이 경로의 파일을 자료 묶음에 추가하지 않는다.

제공된 스크린샷 5장은 `.private/lcu/screens-g1-20261021/S1.png`~`S5.png`에 보존했다. 계정명·친구 목록을 포함하므로 원본 화면은 자료 묶음에 넣지 않는다. 화면 관측값과 대조 절차는 `.private/lcu/record-g1-screen-review.py`에 남겼다.

이번 로컬 준비 절차는 `.private/lcu/prepare-h2-test-data.py`, 원본·표·해시·식별자 재검사는 `.private/lcu/verify-h2-test-data.py`에 남겼다. 준비 스크립트는 기존 결과 폴더를 덮어쓰지 않는다. 재검사 명령은 프로젝트 루트에서 다음과 같다.

```sh
/usr/bin/python3 .private/lcu/verify-h2-test-data.py
```

검사 후 산출물을 변경하면 매니페스트와 ZIP도 다시 생성해야 한다. 원본 식별자나 가명 대응표를 출력하는 용도로 사용하지 않는다.

2026-10-22 재검사에서는 위의 **기존 검증기 실패**를 확인했다. `screen-G1-review.md`의 아이템 검증 설명 두 줄이 C06 후속 대조 내용으로 수정됐지만 기존 manifest/ZIP은 당시 버전으로 남아 있어 해시가 달랐다. 나머지 11개 파일, 원본 source manifest의 모든 파일, 원본 배포 ZIP 해시는 일치했고, 기존 자료 ZIP 안의 화면 검토 문서도 기존 manifest와 일치했다. 과거 묶음을 조용히 재작성하지 않는다. 새 공개 후보는 이 화면 문서를 입력으로 사용하지 않으며 [현재 감사 명령](lcu-candidate-contract.md)으로 별도 원본 대조한다. 기존 검증기의 이번 실행을 PASS로 기록하지 않는다.
