## 확인한 사항

- 현재 계정·목록·경기 상세 3건을 기존 `redact.mjs`의 한 실행에 전달해 가명 일관성을 유지했다. 비교표의 P01~P10은 가명 PUUID에 연결한 읽기용 이름이다.
- 필수 숫자 통계 22개 × 30행 = **660개**가 원본과 일치한다. 가명화 JSON에 남긴 비식별 스칼라 1,639개도 원본과 타입·값이 일치한다. 팀·개인 승패, 5+5 팀, 참가자 번호 연결을 확인했다.
- 경기별 가명 계정은 10개이고 세 경기 전체의 고유 계정도 10개다. 팀·참가자 번호가 달라져도 같은 계정의 가명을 유지한다.
- 목록 응답은 경기당 수집자 1명의 통계만 포함하며 해당 통계는 상세와 일치한다. 전체 10명 비교는 상세 JSON으로 수행한다.
- 원본에 있는 실제 PUUID·계정/소환사/경기 ID·이름·태그의 잔존 검사를 통과했다. 인증 표식과 원본 경로가 없고 실계정 대응표가 묶음에서 제외된 것을 확인했다. 가명화 결과이지 완전한 익명성을 보장하는 자료라는 뜻은 아니다.
- 필수 통계에 누락·null이 없으며 실제 0은 보존했다. 오브젝트 피해 0은 1행, 포탑 피해 0은 4행, item0~5의 0은 7개다. 시야 점수 0의 실제 사례는 없다.
- 생성된 Markdown의 90개 표 행을 다시 읽어 기대값과 대조했다. 30개 참가자 행마다 통계·CS/골드/시야·아이템의 세 표를 제공한다.
- Node.js 24.22.1에서 이번 작업에 해당하는 오프라인 테스트 **3/3 PASS**. 전체 26개 테스트는 샌드박스에서 로컬 HTTPS 포트 열기가 차단되어 5개 통과·21개 `listen EPERM`이었고, 권한 확장 재실행은 사용자 턴 전환으로 중단됐다. 전체 테스트 통과로 기록하지 않는다. 수집 도구 코드는 수정하지 않았다.

## 해석과 사용 범위

- `csCandidateSum`은 `totalMinionsKilled + neutralMinionsKilled`의 계산값이다. 아군·적 정글 하위 필드를 다시 더하지 않는다. G1의 10명 모두 화면 CS와 일치하며 G2·G3 화면 대조는 남아 있다.
- 챔피언 대상 피해·받은 피해·오브젝트 피해·포탑 피해를 분리했다. 오브젝트와 포탑 피해는 중복 포함 여부가 미확인이므로 합산하지 않는다.
- 경기 상세의 `accountId`와 `currentAccountId`는 모두 0이었다. 여러 참가자가 공유하는 자리표시 값이므로 계정 연결에 사용하지 않는다. 이름 대신 PUUID 가명을 사용했다.
- 실제 정수 식별자는 가명 문자열로 바뀐다. 원본 숫자 ID 파싱이나 두 PC의 원본 경기 키 검증에는 비공개 원본이 필요하다.
- 기존 보수적 가명화 정책에 따라 경기 생성 시각·자유 문자열·허용되지 않은 필드는 제거했다. `timeline.role`의 `CARRY`/`SUPPORT`도 기존 허용 목록에 없어 제거됐으며, 이 후보를 완전한 역할 분석 자료로 간주하지 않는다. 요구된 비교 통계는 모두 보존했다.
- 결과 화면 대조는 **G1 숫자 통계·슬롯 점유 일치, 나머지 범위 미확인**이다. G1은 화면의 1번 팀이 teamId=200(승), 2번 팀이 teamId=100(패)에 대응했다. 이를 모든 경기의 고정 대응으로 일반화하지 않는다. 아이템의 정확한 ID는 작은 아이콘만으로 확정하지 않았다. G2·G3 화면·클라이언트 재시작·다른 PC 경기 식별자 비교는 미확인으로 남겼고 전체 gate는 HOLD다.
