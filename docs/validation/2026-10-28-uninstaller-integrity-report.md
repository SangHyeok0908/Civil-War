# Windows 제거 프로그램 무결성 오류와 복구 준비

기록일·편집일: 2026-10-28. 사용자가 자료를 유지한 채 새 수집기로 업데이트할 수 있도록, 손상된 제거 파일을 복원하는 도구와 내부 검사에 통과한 새 설치판을 준비했다. 준비 검증 뒤 사용자가 Windows에서 복구 도구의 정상 완료와 새 백업 경로를 전달했고, 이어 새 설치판 설치 완료를 보고했다. 후속 재실행·같은 판 재설치의 자료 보존 보고는 [경기 수집 후속 기록](2026-10-28-history-pagination-report.md#후속-windows-조회회원-등록-상태)에서 구분한다.

현재 실행 절차는 [설치·복구 안내](../runbooks/collector-install.md#기존-제거-프로그램의-무결성-오류-복구), 판단 이유는 [제거 프로그램 복구 결정](../superpowers/decisions/2026-10-22-overnight-decisions.md#d29--2026-10-28-제거-프로그램-무결성-복구와-배포-차단), 최신 상태는 [상태 정본](../status.md)을 따른다. 앞선 [반복 페이지 수정 기록](2026-10-28-history-pagination-report.md)의 경기 조회 수정은 유지하며, 그때의 외부 해시·로컬 검사 수치를 내부 제거 프로그램 실행 성공으로 고치지 않는다.

## Windows에서 받은 결과

[사용자 실행 근거](assets/nsis-uninstaller-windows-20261028.json)는 이 채팅의 PowerShell 출력과 NSIS 오류 문구를 식별자 없이 정리한 것이다. 실제 설치 등록 버전은 `0.2.0-provisional`, 업데이트 시도는 `0.2.2-provisional`이다.

- 수집기 이름과 기본 설치 경로로 실행 프로세스를 조회했으나 결과가 없었다.
- 기존 제거 파일 한 개가 있었고 크기는 136,123바이트였다. 설치 목록의 빈 `InstallLocation`은 정상 등록 방식이다. 실제 경로는 별도 설치 키에도 저장한다.
- 자료 폴더 전체와 제거 파일을 백업한 뒤 화면이 보이는 방식으로 실행하자 `Installer integrity check has failed`가 표시되고 종료 코드 2를 반환했다.
- 그 뒤에도 자료 폴더와 `credential.bin`이 존재했다. 이 존재 확인을 DB 내용 전수 보존이나 인증 복호화 성공으로 확대하지 않는다.

설치기 소스는 이전 제거 프로그램이 반복 실패할 때도 앱을 닫을 수 없다는 메시지를 사용한다. 따라서 처음 오류를 잔여 프로세스로 단정한 안내는 수정했다. 당시 실패 출력에는 현장 제거 파일의 SHA-256 값이 없었으므로 원본과의 바이트 동일성은 복구 도구 실행 때 확인하도록 했다. 후속 실행 결과는 아래에 별도로 기록한다.

## 배포 원본 대조와 원인

macOS arm64·Node.js 24.22.1에서 보관한 배포 설치 파일을 7-Zip으로 읽었다. [이전 판 감사](assets/nsis-previous-release-audit-20261028.json)에서 세 배포판의 내부 제거 프로그램이 모두 CRC 검사에 실패했다. 설치판의 바깥 해시가 맞고 최초 설치가 동작하더라도 이 결함은 남을 수 있었다.

상위 [문제 보고](https://github.com/electron-userland/electron-builder/issues/10258)와 [수정 PR](https://github.com/electron-userland/electron-builder/pull/10262)을 설치된 코드와 대조했다. Windows용 제거 프로그램을 macOS에서 추출하는 코드가 설치용 실행부를 복사하면서 제거용 아이콘 변경 기록을 적용하지 않았다. 기본 설치·제거 아이콘도 서로 달라 현재 설정에서 재현된다. 크기 차이나 NSIS 시작 위치가 틀렸다는 결론은 채택하지 않았다.

| 원본 대조 항목 | 관측·검사 결과 |
| --- | --- |
| 보관한 기존 제거 파일의 크기 | Windows 보고와 같은 136,123바이트 |
| 원본에 저장된 CRC32 | `12b43385` |
| 복구 전 실제 바이트의 CRC32 | `5b4c31ab` — 저장값과 불일치 |
| 아이콘 변경 기록 적용 | 8개 기록, 아이콘 영역 7,960바이트 변경 |
| 복구 후 실제 바이트의 CRC32 | `12b43385` — 원래 저장값과 일치 |
| 변경하지 않은 부분 | 제거 코드·자료가 들어 있는 본문과 저장된 CRC 값 |

이 비교는 [복구 파일 감사](assets/nsis-uninstaller-recovery-20261028.json)에 해시와 함께 기록했다. 복구 파일은 새 검사값을 덮어써 맞춘 것이 아니라 누락한 아이콘 기록을 복원한 것이다. 현장 파일의 원본 해시가 이 감사와 다르면 자동 교체하지 않는다.

## 변경과 확인 범위

고정된 패키징 도구에 [버전 한정 패치](../../patches/app-builder-lib@26.18.0.patch)를 등록했다. 패치에서 아이콘 변경과 원래 CRC 검사를 수행하고, [배포 실행기](../../scripts/package-collector.mjs)는 최종 설치 파일 안에 실제로 들어간 제거 프로그램도 별도로 검사한다. CRC가 꺼진 파일·길이 오류·값 불일치를 배포 성공으로 처리하지 않는다. 이번 지원 범위는 기존 고정 NSIS 도구와 현재의 기본 아이콘·비고체 압축 설정이다.

복구 도구는 현재 Windows 사용자 설치 경로에서 알려진 기존 해시만 허용한다. 자료 폴더와 기존 제거 파일을 새 백업 폴더에 복사하고 원본을 다시 확인한 뒤 제거 파일 하나를 교체한다. 경기 DB·암호화 인증·설치 레지스트리를 수정하거나, 제거 프로그램을 도구가 직접 실행하지 않는다. 재실행 시 이미 같은 복구 파일이면 교체하지 않는다.

| 실행 환경·검사 | 결과 | 근거·한계 |
| --- | --- | --- |
| macOS arm64의 실제 NSIS 기본 아이콘 생성·추출 | 수정 전 CRC 불일치 재현, 패치 후 일치 | [재현 검사](../../scripts/nsis-integrity.test.mjs). 실제 Windows 실행은 아님 |
| 기존 배포 검사와 새 무결성·복구 검사 | 사례 12개 통과 | [기존 검사](../../scripts/collector-release.test.mjs), [무결성 검사](../../scripts/nsis-integrity.test.mjs), [복구 검사](../../scripts/repair-uninstaller.test.mjs). 각각 5·3·4개 사례 |
| 실제 구 배포 제거 파일과 합성 자료 폴더의 복구 | 교체·자료 동일성·백업 확인 | [파일시스템 실행 근거](assets/nsis-recovery-filesystem-20261028.json). 실제 원본 EXE, 합성 DB·인증·WAL 파일을 사용. Windows 프로세스 조회는 대체했으므로 실제 기기 확인과 구분 |
| 새 설치판 생성·외부 해시·내부 CRC 검사 | 통과 | [새 산출물 감사](assets/nsis-fixed-release-20261028.json). 버전과 내장 제거 파일 해시·CRC를 기록 |
| 새 판의 수집기 코드 대조 | 이전 수정판의 main·preload와 바이트 일치 | 같은 산출물 감사에 기록. 그때의 [Electron 시나리오 8개](2026-10-28-history-pagination-report.md#수정과-재현-검사)를 이번 판의 새 실행 수로 세지 않음 |
| 수집기 단위·타입·형식·문서 검사 | 단위 사례 64개·문서 검사기 사례 66개 통과, 타입·형식·정본·링크·중복·공백 검사 통과 | `pnpm test`, `pnpm typecheck`, `pnpm format:check`, `pnpm test:docs`, `pnpm docs:check`, `git diff --check`. 실제 Windows 확인을 대신하지 않음 |

읽기 전용 독립 검토에서도 원본·복구 해시 검사, 백업·원본 재확인, 내부 검사와 패치 해시를 대조했고 차단할 문제를 보고하지 않았다. 별도 실행한 검사 7개는 위 12개와 겹치므로 합산하지 않는다. 검토 담당자도 실제 Windows 설치를 실행하지 않았다.

## 후속 Windows 복구 사용자 확인

2026-10-28 사용자는 전달받은 복구 폴더에서 `node .\repair-uninstaller.mjs --repair`를 실행하고 `status: repaired`와 새 `backupDirectory` 출력을 전달했다. [후속 실행 근거](assets/nsis-recovery-windows-result-20261028.json)에는 개인 경로를 제외한 결과만 남겼다.

제공한 도구의 이 성공 경로는 원본·복구 해시 확인, 자료·원본 제거 파일 백업, 대상 재확인·교체와 교체 후 해시 확인을 마쳤다는 뜻이다. 사용자 실행 보고에 근거한 확인이며 담당자가 Windows를 직접 조작한 결과와 구분한다. 준비 당시 미실행으로 기록한 산출물 감사의 값은 바꾸지 않는다.

같은 날 사용자는 `0.2.3` 설치 완료도 보고했다. 이 보고는 설치 화면의 완료 확인이며, 별도의 파일 버전 출력·이전 제거 프로그램 실행 로그는 아직 받지 않았다. 이후 온라인 확인은 정상이고 오프라인 경기 조회에서 참가자 미등록 안내가 나왔다고 보고했다. 경기 조회 후속 관측은 [별도 기록](2026-10-28-history-pagination-report.md#후속-windows-조회회원-등록-상태)으로 구분한다. 복구·설치 완료 보고를 대기 자료 보존 시험의 통과로 세지 않는다.

## 산출물·남은 확인

### 후속 Windows 자동 검사의 추출 경로 수정

수집기 설치·복구 초안 PR [#7](https://github.com/SangHyeok0908/Civil-War/pull/7)의 최초 커밋 `1d83e3a`에서 Windows 자동 검사 두 실행이 모두 설치판 생성 후 `UNINSTALLER_EXTRACTION_FAILED`로 실패했다. [첫 실행](https://github.com/SangHyeok0908/Civil-War/actions/runs/40645402763)과 [두 번째 실행](https://github.com/SangHyeok0908/Civil-War/actions/runs/40645703214)에서 단위 사례 64개·배포 사례 12개·Electron 시나리오 8개는 통과했고, 최종 설치 파일에서 제거 프로그램을 꺼내는 단계에서 멈췄다. 같은 커밋의 [서버 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40645703163)는 성공했다.

[추출 코드](../../scripts/nsis-integrity.mjs)는 7-Zip에 전달하는 내부 경로를 `/`로 고정하고 있었다. macOS의 실제 설치판에서 해당 구분자는 제거 파일을 반환했지만 반대 구분자로 요청하면 종료 코드 0·출력 0바이트가 됐다. 내부 경로도 실행 운영체제의 구분자로 만들도록 수정했다. 제거 파일의 원래 CRC를 확인하는 검사는 그대로 유지한다.

[기존 실제 NSIS 회귀 사례](../../scripts/nsis-integrity.test.mjs)를 보강해 생성한 제거 프로그램을 최종 설치 파일에 넣고, 같은 검증 함수로 다시 추출한 크기·저장 CRC를 대조한다. macOS의 배포·복구 사례 12개, 단위 사례 64개와 기존 설치판 재검증은 통과했다. 수정 후 실제 Windows 자동 검사의 결과는 [PR 검사 목록](https://github.com/SangHyeok0908/Civil-War/pull/7/checks)에서 확인하며, 로컬 성공을 Windows 실행 성공으로 바꾸지 않는다.

### 배포판과 운영 확인

새 판은 `0.2.3-provisional`이며 기존 `0.2.0`·`0.2.1`·`0.2.2` 배포는 비교 근거로 보존한다. 이전 설치판을 새 설치·재설치 기준으로 재사용하지 않는다. 복구 ZIP에는 새 설치 파일, 원본과 바깥 해시로 연결한 복구 파일, 허용 해시 메타데이터, Node.js 도구와 안내만 넣으며 실제 사용자 자료는 포함하지 않는다.

현재 남은 실기는 [상태 정본](../status.md#남은-작업-순서)을 따른다. 다른 기기의 복구에서 알 수 없는 원본이나 실행·접근 오류가 나면 그 코드로 멈춘다. 복구·설치 완료 보고만으로 Windows 자료 보존 시험 전체를 완료 처리하지 않는다.

패치 수정이 정식 도구에 반영되어 동일 검사를 통과하면 이식 패치 제거를 검토한다. 무결성 검사 해제, 과거 기록·설치 등록 정보 수동 삭제, 새 내전, 범위에서 제외한 과거 조회 측정은 이번 대응에 포함하지 않는다.
