# Windows 자료 보존·인증 복구 시험 준비 결과

기록일·편집일: 2026-10-26. 사용자는 집 Windows의 Docker Desktop·Cloudflare Tunnel에 시험 서버를 배포하고, 첫 설치판에서 자료 보존·인증 복구를 시험할 수 있다. 담당자는 배포 묶음과 버전 교체 시험판을 만들고 로컬 서버·DB 연동을 확인했다. 실제 배포·Windows 조작은 사용자 담당이며 아직 그 결과를 받지 않았다.

실행 순서는 [서버 배포 정본](../runbooks/home-server.md)과 [Windows 실기 정본](../runbooks/collector-acceptance.md)에 있다. 최신 상태는 [진행 상태](../status.md), 이전 기본 설치 결과는 [첫 설치 사용자 확인](2026-10-26-windows-installer-report.md#후속-windows-기본-설치-사용자-확인)으로 구분한다.

## 환경과 변경 범위

macOS arm64, Node.js 24.22.1·pnpm 11.5.0·JDK 25.0.1·Docker Engine 28.1.1에서 준비했다. Docker의 실제 Spring 서버 JAR·PostgreSQL을 사용했고, 자동 검사 DB와 다른 프로젝트·DB·볼륨으로 배포 구성을 실행했다. 이미지 버전·해시의 원본은 [Compose](../../infra/home-server/compose.yml)와 [Dockerfile](../../infra/home-server/Dockerfile)이다.

| 분류·상태 | 주체 | 이번 처리 | 지금 판단할 사항 |
| --- | --- | --- | --- |
| 사용자 확정 | 사용자, 후속 시험 요청과 기존 배포 합의 재확인 | Windows 직접 조작·실제 배포는 사용자가 수행 | 배포 환경 재선택 없음 |
| 위임받은 선택·준비 완료 | 담당자 | 시험 전용 DB·고정 이미지·비밀 파일 방식과 버전 교체 시험판 마련 | 실제 시험에서 문제 발견 시 조정 |
| 조사 및 검증·환경 한정 | 담당자 | 로컬 컨테이너·API·기존 수집기 검증 | 아래 미확인 범위는 실기 결과가 필요 |

수집기 버전은 `0.2.0-provisional`에서 `0.2.1-provisional`로 올렸다. 기존 설치판과 해시 목록은 별도 폴더에 보존했다. 새 app.asar(앱 코드 묶음)의 버전·x86-64 실행 파일을 확인했고, main·preload 코드는 보관한 이전 설치용 빌드와 바이트가 같았다. 저장 구조·설치 식별자·제품 화면을 새로 구현한 판이 아니라 **버전 간 파일 교체를 시험하기 위한 판**이다. [산출물 감사](assets/collector-acceptance-release.json)에 크기·해시·검사 범위를 남겼다.

실제 HTTP 확인은 **로컬 시험용 포트 덧설정**과 합성 회원을 사용했다. 원본 Compose는 바꾸지 않았으며 개발용 HTTP 프로필도 켜지 않았다. HTTPS 출처를 명시한 요청과 Secure 쿠키 발급은 확인했지만, 이 결과는 실제 외부 HTTPS 전송이나 Cloudflare 통과 검증이 아니다. 쿠키를 시험 요청에 직접 전달한 것이므로 브라우저의 HTTPS 쿠키 전달까지 확인한 결과로 확대하지 않는다.

원격 CI(지속적 통합 검사)나 실제 Windows 설치 실행을 대신하지 않는다. 상세 실행 로그·로컬 검증 실행기는 `.private/collector-acceptance/`에 보관했다. 이 폴더에는 시험 환경 설정도 있으므로 통째로 공개하지 않는다. 공개 JSON에는 코드·토큰·원본 식별자를 넣지 않았다.

별도 검토 에이전트가 배포 설정·관리 화면 라벨·오프라인 대기·같은 회원의 명시적 재개를 현재 코드와 대조했고, 실행을 막는 발견은 보고하지 않았다. 실제 Windows 명령 실행이나 외부 Cloudflare 연결을 대신하는 검토는 아니다.

## 준비 중 발견·수정한 사항

- 최초 서버 상태 검사가 기본 Java 이미지에 없는 `curl`을 호출했다. 서버는 시작했으나 상태 검사가 실패한 것을 확인한 뒤, 고정 이미지의 Bash로 HTTP 상태 줄을 검사하도록 바꾸고 DB·서버 모두 `healthy`를 확인했다.
- 수집기 버전 변경 뒤 pnpm의 의존성 상태 재확인이 비대화형 환경에서 중단됐다. 고정 잠금 파일 설치를 명시적으로 수행한 뒤 단위·타입·배포 검사가 통과했다. 제품 의존성 버전은 추가로 바꾸지 않았다.
- 임시 HTTP 실행기는 컨테이너 교체 뒤 이전 연결을 재사용해 연결 초기화 오류를 냈다. 합성 회원 중복을 피하고 요청마다 연결을 닫도록 실행기를 수정한 뒤 최종 17항목을 한 번에 통과했다. 서버 오류 수정이나 Windows 성공으로 기록하지 않는다.

## 남은 필수 실기와 범위 제외

미실행 필수 항목은 집 Windows에서의 실제 Compose 배포·Cloudflare 공개 주소 연결·실제 회원 코드 발급·기기 인증 보호·대기 자료 생성·제거 후 재설치·서로 다른 설치판의 업데이트·인증 손상 후 본인 요청 재개다. 이 기록의 로컬 합성 회원 코드는 실제 배포 서버의 등록 코드로 전달하지 않는다. 사용자가 배포한 서버에서 새 코드를 발급해야 한다.

새 내전·조회 시점 비교·과거 조회 범위 측정·시범 운영은 이번 완료 조건에 포함하지 않는다. 진단 내보내기·자동 업데이트·운영 DB 이전·PC 밖 백업 복원·Windows 재부팅 후 운영 복구도 이번 준비의 구현·검증 성과로 기록하지 않는다.
