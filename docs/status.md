# 현재 구현·검증 상태

기록일: **2026-10-24**. 편집·보완일과 현재 상태 기준일: **2026-10-28**. 이 문서는 현재 진행 상태의 정본이다. 제품이 따라야 할 기준은 [명세](spec.md), 과거 실행 결과는 각 검증 보고서를 따른다. 기준 확정, 코드 구현, 실제 환경 검증은 서로 다른 상태다.

## 단계별 확인 범위

[후속 준비](validation/2026-10-26-collector-acceptance-preparation.md)에 배포 묶음·로컬 검증 | 집 서버의 남은 운영·복원 확인. 이번 추가 Windows 시험 제외는 아래 표 참조 |

LCU는 League Client API(게임 클라이언트의 로컬 인터페이스), JAR는 자바 실행 묶음, CI는 변경마다 실행하는 지속적 통합 검사다. 시험 자료의 식별자·시각은 합성 또는 가명이다. 로컬·호스팅 시험 응답 성공을 실제 League·Windows 인증 보호나 운영 가용성 검증으로 확대하지 않는다. 테스트 개수와 실행 환경은 당시 보고서를 참조하며 여기서 최신 실행 수처럼 복사하지 않는다.

## 최근 오류 수정과 자동 검사

기존 배포판의 제거 프로그램이 손상된 상태로 만들어져 Windows 업데이트가 막혔다. [무결성 보고서](validation/2026-10-28-uninstaller-integrity-report.md)에 사용자 오류와 원본 검사, 수정한 빌드 도구·복구 묶음의 범위를 기록했다. 예전 설치판의 바깥 해시 검증 성공은 내부 제거 프로그램 실행 성공을 뜻하지 않았으며, 해당 판을 새 설치·재설치 기준으로 재사용하지 않는다.

2026-10-28에는 다른 페이지를 요청해도 같은 목록이 반환될 때 확보한 경기까지 수집하지 못하던 처리를 수정했다. 사용자 진단의 실제 관측과 수정판의 가상 응답 검사는 [반복 페이지 보고서](validation/2026-10-28-history-pagination-report.md)에서 구분한다. 페이지 조회 범위가 넓어진 것과 실제 Windows 자료 보존 성공을 뜻하지 않는다.

2026-10-26에는 [공개 후보 자료의 설명 파일 허용값 검사](https://github.com/SangHyeok0908/Civil-War/commit/7ee680d6da58f6302afad0ee3d666b552b3b0f7c)와 [늦은 목록 응답에 의한 수집기 등록 상태 역행 방지](https://github.com/SangHyeok0908/Civil-War/commit/9391475e48b62d5b1f1d370974b7b4058427e93e)를 반영했다. 기존 PR #1–#4는 순서대로 `master`에 병합했다. 이는 오류 수정과 개발 이력 통합이며, 위 표의 미완료 기능이나 실제 환경 검증을 완료한 것으로 바꾸지 않는다.

두 수정이 포함된 커밋 `eab0ed6`의 [서버·웹 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496591), [Windows 앱 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496596), [형식 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496598) 성공을 확인했다. 서버·웹 검사는 실제 PostgreSQL과 브라우저를 사용하고, Windows 앱 검사의 게임 연결은 가상 응답이다. 기존 PR 4개를 병합한 커밋 `0df5352`의 파일 내용은 이 커밋과 같으며, 이번 문서 정리의 새 검사 결과는 해당 PR에 별도로 기록한다.

## 남은 작업 순서

확정 평가 기준 반영과 보관 경기 전체의 재계산 검증은 2026-10-26에 마쳤다. [실행 범위·결과](validation/2026-10-26-confirmed-objective-report.md)는 격리 DB 기준이며 운영 배포 완료를 뜻하지 않는다.

사용자는 [후속 관측](validation/2026-10-28-history-pagination-report.md#후속-windows-조회회원-등록-상태)에서 재설치 보존, 기존 인증의 연결 복구, 추가 한 경기의 명시적 등록을 포함한 등록 완료 2건·확인 대기 1건, 서버 중복 없음·포지션 일치와 마지막 재실행 상태 유지를 보고했다. 선택한 Windows 실기는 사용자 실행 보고 기준으로 완료했다. [D30](superpowers/decisions/2026-10-22-overnight-decisions.md#d30--2026-10-28-업데이트인증-손상-시험-제외와-기존-요청-처리)의 두 시험과 후속 시험판 준비는 다시 요구하지 않는다.

1. [집 Windows 서버](runbooks/home-server.md#5-중단재개와-남은-운영-확인)의 DB를 PC 밖에 백업하고 별도 DB로 복원해 자료를 확인한다. 현재 서버의 자료를 복원 시험으로 덮어쓰지 않는다. 수집기 폴더 백업과 서버 DB 백업은 서로 다른 자료다(T14).
2. Docker Desktop 자동 시작·Windows 절전과 재부팅 후 복구, 외부 회선에서의 웹·운영자 접근, 프록시 환경의 요청 제한을 확인한다. 현재 서버 웹 조회 성공을 별도 외부 회선·재부팅·복원 확인으로 확대하지 않는다(T12·T14).
3. 배포 서버의 실행 버전·계산 버전과 등록 경기 집계를 대조하고, 미반영 변경이 있을 때 적용한다. 격리 DB의 기존 계산 검증을 운영 DB의 전수 대조로 세지 않는다.
4. 오류 코드·버전·상태만 담는 수집기 진단 내보내기는 후속 구현으로 남는다(T13). 공식 솔로랭크 참고의 현재 연동 제한은 아래 표와 같이 별도로 관리한다.

세부 수용 절차의 기존 근거는 [2단계 Windows 확인 항목](validation/stage2-report.md#exact-outstanding-windows-manual-run--hold)과 [당시 개발 계획의 설치·배포 작업](superpowers/plans/2026-10-21-lol-inhouse-development-plan.md#t13-windows-설치업데이트진단)이다. 새 작업을 시작할 때 이 문서의 최신 범위와 대조해 실행 계획을 작성한다.

## 범위 제외와 미확인 사실

| 구분 | 항목 | 처리 |
| --- | --- | --- |
| 사용자 결정으로 제외 | C01 경기 종료 후 첫 실행 조회, C02 선행 실행 도구·새 프로세스 비교, C10 반영 지연·과거 조회 범위 측정, T15 실제 3–5경기 시범 운영 | 일정·남은 작업·출시 조건으로 다시 넣지 않음 |
| 이번 사용자 요청으로 제외 | 버전 간 업데이트·인증 손상 복구 실기와 이를 위한 후속 시험판 준비 | [D30](superpowers/decisions/2026-10-22-overnight-decisions.md#d30--2026-10-28-업데이트인증-손상-시험-제외와-기존-요청-처리). 미실행·미검증이며 통과로 기록하지 않음 |
| 기존 사용자 결정으로 제외 | G2·G3 추가 화면, 클라이언트 재시작 후 동일 경기 조회, 다른 PC 경기 키 대조, 친구 목록 조회 | 기존 관측은 보존하되 새 측정이나 PASS로 바꾸지 않음. [범위 근거](validation/lcu-report.md) |

| 현재 연동 제한 | 수집기 솔로 참고 실시간 내보내기, 운영 서버의 직접 Riot HTTP 연동 | 공식 포털에서 다른 참가자 1명의 6경기 조회 성공과 구분. [당시 접근 증거](validation/riot-solo-reference.md) |

사용자 지시로 제외한 항목은 미완료 필수 작업이 아니다. 새로운 사용자 범위 변경 지시가 있을 때만 다시 검토한다.
