## 2026-10-28 사용자 경험 변경 반영

참가자 입력, 게스트 연결, 공통 코드와 수집기 확인·진행·목록 화면을 격리 작업 공간에 구현했다. 세부 검증 결과와 재현 근거는 [이번 실행 보고서](validation/2026-10-28-ux-implementation-report.md)에 있다. 제품 목표와 개발자의 선택은 [명세](spec.md)·[결정 기록](superpowers/decisions/2026-10-28-ux-requirements.md)에서 구분한다.

| 분류·주체 | 현재 상태 | 지금 판단할 사항 |
| --- | --- | --- |
| 사용자 확정 · 사용자 | R01–R27의 코드 반영 요청에 따라 구현 | 기존 제품 결정을 다시 승인받지 않음 |

| 위임받은 선택 · 개발 담당자 | 계정 키 분리·등급 정책·로컬 챔피언 자산·동시 인증 제한 채택 | 비용·재검토 조건은 결정 기록 참조 |

운영 서버·사용자 PC 자료는 이번 자동 검사의 대상이 아니다. 배포를 요청받으면 아래 적용 순서를 사용하며, 이전 실기 증거와 제외 범위는 유지한다.

## 사용자 경험 변경의 배포 ZIP 준비

사용자는 코드 반영 뒤 운영 적용에 쓸 ZIP 생성을 요청했다. 서버와 새 수집기·교체 안내·무결성 확인값을 묶어 로컬 ZIP을 생성했다. 기존에 제외한 Windows 실기는 이번 생성 검사에 포함하지 않았다. 생성·검증 결과는 [배포 묶음 보고서](validation/2026-10-28-ux-deployment-package-report.md)에 기록한다. ZIP 생성은 사용자 서버에 적용하거나 외부로 게시한 결과가 아니다.

## 기존 UX 작업의 후속 간소화

사용자의 추가 요청에 따라 자동 전송 재개·연결 팝업·세 경기 페이지·직접 등록·설치판 고정 서버와 실행 기본값·고정 관리자 로그인·숫자 모임 코드를 반영했다. [후속 실행 보고서](validation/2026-10-28-ux-followup-report.md)에서 이전 검사와 이번 검사를 구분하며, 새 0.4 설치판·배포 ZIP의 생성과 무결성 검사는 완료했고 실제 Windows 실행과 운영 적용은 미확인이다. 이전 배포 ZIP은 이 후속 변경 전 버전이므로 새 구현 결과로 표시하지 않는다. 문서 대조에서 확인한 인증 오류 안내 두 곳은 2026-10-29에 모임 코드 재입력과 동일 계정 확인 후 자동 재개를 안내하도록 수정했다. [후속 수정 기록](validation/2026-10-28-ux-followup-report.md#2026-10-29-인증-오류-안내-수정)을 따르며 기존 설치 파일·ZIP은 이번 문구 수정을 포함하지 않는다.

## 2026-10-29 수집기 솔로랭크 기능 제거

수집기 버튼과 내보내기 내부 연결을 제거했다. 솔로랭크 활용 범위는 [웹 팀 추천](spec.md#포지션별-실력-보정)이며 수집기 재구현 과제로 남기지 않는다. 이번 작업은 `codex/participant-collector-ux`의 기존 계정 연결·등급 보정 구현을 보존한다.

처음 수행한 master 조사에서는 자동 보정이 없었지만 이 브랜치에는 이미 공식 등급 기반 시작값이 구현돼 있다. 두 코드 기준을 섞지 않는다. [작업 이동 후 재검증](validation/2026-10-29-team-solo-report.md#대상-브랜치로-이동한-뒤-재검증)에서 실제 서버 계산과 외부 가상 응답·실연동의 구분을 기록한다.

## 2026-10-29 밝은 디자인과 참가자 사진

웹·수집기 화면과 참가자 사진 조회·캐시를 구현했다. 로컬 전체 서버·웹·Electron 검사와 독립 코드 검토를 마쳤다. [이번 화면·사진 보고서](validation/2026-10-29-light-ui-report.md)에 실행 환경·사례 수·이미지와 한계를 구분한다. [제품 기준](spec.md#화면-디자인과-참가자-사진)과 [선택 기록](superpowers/decisions/2026-10-29-light-ui.md)은 실제 운영 배포와 구분한다.

이 작업은 `codex/participant-collector-ux`의 당시 미커밋 변경까지 보존한 `codex/toss-light-ui` 작업 폴더에서 수행했다. 원래 작업 폴더의 변경을 덮어쓰지 않았다. 실제 Riot 키 조회·실제 Windows 화면·운영 배포는 별도 미확인이다.

## 2026-11-21 운영자 로그인 코드의 서버 설정 이동

고정 운영자 코드가 공개 저장소의 서버 코드에 들어 있어, 서버 주소를 아는 사람은 누구나 운영자 권한을 얻을 수 있었다. 이제 서버는 이 값을 서버 PC `.env`의 `ADMIN_LOGIN_CODE`에서 읽는다. 값이 없거나, 8–128자를 벗어나거나, 앞뒤 공백이 있거나, 예시 값이면 서버가 시작하지 않는다. 반복 로그인과 기존 실패 제한은 그대로다. 이유와 대안 비교는 [결정 기록](superpowers/decisions/2026-10-28-ux-requirements.md#2026-11-21-보완--운영자-로그인-코드를-서버-비밀-설정으로-이동), 실행 결과는 [검증 보고서](validation/2026-11-21-admin-login-setting-report.md)에 있다.

| 분류·주체 | 현재 상태 | 지금 판단할 사항 |
| --- | --- | --- |
| 사용자 확정 · 사용자 | 코드 밖 서버 비밀 설정으로 이동 지시 | 없음 |
| 위임받은 선택 · 구현 담당자 | `.env` 환경 변수, 8–128자, 누락 시 시작 거부 | 운영 적용 때 `.env`·`compose.yml`에 값 추가 필요 |
| 미확인 | 실제 집 서버에 새 설정 적용, 이전 고정값 거부의 운영 확인 | 운영 적용 시 확인 |

## 2026-11-27 Riot 키 교체 뒤 솔로랭크 반영 복구

운영 Riot 키를 바꾼 뒤에는 팀 추천이 참가자의 최신 등급을 반영하지 못하고 이전 값만 썼다. Riot이 키마다 다른 계정 식별값(PUUID)을 주는데 서버가 이를 계정 충돌로 처리했기 때문이다. 이제 서버는 저장 값이 이전 키의 것인지 Riot에 확인하고, 그럴 때만 새 값으로 바꿔 등급을 반영한다. 관측과 시험은 [검증 보고서](validation/2026-11-27-riot-key-change-report.md), 선택 이유는 [설계 기록의 보완](superpowers/specs/2026-11-25-team-live-solo-rank-design.md#2026-11-27-보완--api-키-교체-뒤-저장된-puuid-갱신)에 있다.

| 분류·주체 | 현재 상태 | 지금 판단할 사항 |
| --- | --- | --- |
| 조사 및 검증 · 개발 담당자 | 운영 서버 실제 조회 1회: 9명 충돌, 1명 계정 없음, 최신 등급 반영 0명 | 없음 |
| 오류 수정 · 개발 담당자 | 저장 값 갱신 구현, 로컬 서버 시험 통과. 사용자 지시로 `master`에 직접 병합 | 없음 |
| 위임받은 선택 · 개발 담당자 | Riot에 저장 값을 확인한 뒤 교체하는 방식 | 바꾸고 싶으면 알림 |
| 조사 및 검증 · 개발 담당자 | 2026-11-28 운영 반영 후 실제 조회 1회: 9명 최신 등급 반영, 충돌 0명, 계정 없음 1명 | 없음 |

## 2026-11-27 운영자 화면과 공개 화면의 사용성 개선

운영자가 경기 정정·평가 기준·점수 재계산·변경 이력·코드와 인증 화면을 설명 없이 이해하고, 되돌릴 수 없는 조작을 확인 없이 실행하지 않도록 웹 화면을 바꿨다. 공개 화면은 활약 점수를 이름 옆에 두고 반복되던 상태 표시와 내부 값을 없앴다. 서버 코드와 API 응답은 바꾸지 않았다. 변경 내용과 이유는 [결정 기록](superpowers/decisions/2026-11-27-operator-ux.md), 시험 결과와 화면은 [검증 보고서](validation/2026-11-27-operator-ux-report.md)에 있다.

| 분류·주체 | 현재 상태 | 지금 판단할 사항 |
| --- | --- | --- |
| 사용자 확정 · 사용자 | 요청한 여섯 가지와 승인한 열두 가지 구현 | 없음 |
| 임시 선택 · 개발 담당자 | 경기 정정 목록을 화면에서 10개씩 나눔, 원본 수치는 화면에서만 제거, 변경 이력은 화면에서 쉬운 말로 변환 | 바꾸고 싶은 항목이 있으면 알림 |
| 범위 제외 | 메뉴 이동 때 페이지 전체를 다시 불러오는 구조 | 별도 작업으로 진행할지 |
| 미확인 | 운영 서버 반영 후의 실제 화면, 실제 휴대전화 기기 | 로컬 시험 서버와 브라우저의 좁은 화면 흉내로만 확인 |

LCU는 League Client API(게임 클라이언트의 로컬 인터페이스), JAR는 자바 실행 묶음, CI는 변경마다 실행하는 지속적 통합 검사다. 시험 자료의 식별자·시각은 합성 또는 가명이다. 로컬·호스팅 시험 응답 성공을 실제 League·Windows 인증 보호나 운영 가용성 검증으로 확대하지 않는다. 테스트 개수와 실행 환경은 당시 보고서를 참조하며 여기서 최신 실행 수처럼 복사하지 않는다.

## 최근 오류 수정과 자동 검사

기존 배포판의 제거 프로그램이 손상된 상태로 만들어져 Windows 업데이트가 막혔다. [무결성 보고서](validation/2026-10-28-uninstaller-integrity-report.md)에 사용자 오류와 원본 검사, 수정한 빌드 도구·복구 묶음의 범위를 기록했다. 예전 설치판의 바깥 해시 검증 성공은 내부 제거 프로그램 실행 성공을 뜻하지 않았으며, 해당 판을 새 설치·재설치 기준으로 재사용하지 않는다.

수집기 설치·복구 초안 PR [#7](https://github.com/SangHyeok0908/Civil-War/pull/7)의 초기 Windows 자동 검사에서는 최종 설치판의 제거 파일 추출이 실패했다. [후속 경로 수정과 회귀 검증](validation/2026-10-28-uninstaller-integrity-report.md#후속-windows-자동-검사의-추출-경로-수정)을 추가했으며, 원격 재검사 결과는 해당 PR의 검사 목록을 따른다. 이 수정은 개발 환경의 배포 검사 경로에 한정되며 사용자 경기·인증 자료를 변경하지 않는다.

2026-10-28에는 다른 페이지를 요청해도 같은 목록이 반환될 때 확보한 경기까지 수집하지 못하던 처리를 수정했다. 사용자 진단의 실제 관측과 수정판의 가상 응답 검사는 [반복 페이지 보고서](validation/2026-10-28-history-pagination-report.md)에서 구분한다. 페이지 조회 범위가 넓어진 것과 실제 Windows 자료 보존 성공을 뜻하지 않는다.

2026-10-26에는 [공개 후보 자료의 설명 파일 허용값 검사](https://github.com/SangHyeok0908/Civil-War/commit/7ee680d6da58f6302afad0ee3d666b552b3b0f7c)와 [늦은 목록 응답에 의한 수집기 등록 상태 역행 방지](https://github.com/SangHyeok0908/Civil-War/commit/9391475e48b62d5b1f1d370974b7b4058427e93e)를 반영했다. 기존 PR #1–#4는 순서대로 `master`에 병합했다. 이는 오류 수정과 개발 이력 통합이며, 위 표의 미완료 기능이나 실제 환경 검증을 완료한 것으로 바꾸지 않는다.

두 수정이 포함된 커밋 `eab0ed6`의 [서버·웹 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496591), [Windows 앱 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496596), [형식 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496598) 성공을 확인했다. 서버·웹 검사는 실제 PostgreSQL과 브라우저를 사용하고, Windows 앱 검사의 게임 연결은 가상 응답이다. 기존 PR 4개를 병합한 커밋 `0df5352`의 파일 내용은 이 커밋과 같으며, 이번 문서 정리의 새 검사 결과는 해당 PR에 별도로 기록한다.

## 남은 작업 순서

확정 평가 기준 반영과 보관 경기 전체의 재계산 검증은 2026-10-26에 마쳤다. [실행 범위·결과](validation/2026-10-26-confirmed-objective-report.md)는 격리 DB 기준이며 운영 배포 완료를 뜻하지 않는다.

사용자는 [후속 관측](validation/2026-10-28-history-pagination-report.md#후속-windows-조회회원-등록-상태)에서 재설치 보존, 기존 인증의 연결 복구, 추가 한 경기의 명시적 등록을 포함한 등록 완료 2건·확인 대기 1건, 서버 중복 없음·포지션 일치와 마지막 재실행 상태 유지를 보고했다. 선택한 Windows 실기는 사용자 실행 보고 기준으로 완료했다. [D30](superpowers/decisions/2026-10-22-overnight-decisions.md#d30--2026-10-28-업데이트인증-손상-시험-제외와-기존-요청-처리)의 두 시험과 후속 시험판 준비는 다시 요구하지 않는다.

1. [집 Windows 서버](runbooks/home-server.md#5-중단재개와-남은-운영-확인)의 DB를 PC 밖에 백업하고 별도 DB로 복원해 자료를 확인한다. 현재 서버의 자료를 복원 시험으로 덮어쓰지 않는다. 수집기 폴더 백업과 서버 DB 백업은 서로 다른 자료다(T14).
2. Docker Desktop 자동 시작·Windows 절전과 재부팅 후 복구, 외부 회선에서의 웹·운영자 접근, 프록시 환경의 요청 제한을 확인한다. 현재 서버 웹 조회 성공을 별도 외부 회선·재부팅·복원 확인으로 확대하지 않는다(T12·T14).
3. 배포 서버의 실행 버전·계산 버전과 등록 경기 집계를 대조하고, 미반영 변경이 있을 때 적용한다. 격리 DB의 기존 계산 검증을 운영 DB의 전수 대조로 세지 않는다.
4. 오류 코드·버전·상태만 담는 수집기 진단 내보내기는 후속 구현으로 남는다(T13). 공식 솔로랭크 참고의 현재 연동 제한은 아래 표와 같이 별도로 관리한다.

세부 수용 절차의 기존 근거는 [2단계 Windows 확인 항목](validation/stage2-report.md#exact-outstanding-windows-manual-run--hold)과 [당시 개발 계획의 설치·배포 작업](superpowers/plans/2026-10-21-lol-inhouse-development-plan.md#t13-windows-설치업데이트진단)이다. 새 작업을 시작할 때 이 문서의 최신 범위와 대조해 실행 계획을 작성한다.
