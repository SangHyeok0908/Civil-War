# 현재 구현·검증 상태

기록일: **2026-10-24**. 편집·보완일과 현재 상태 기준일: **2026-10-26**. 이 문서는 현재 진행 상태의 정본이다. 제품이 따라야 할 기준은 [명세](spec.md), 과거 실행 결과는 각 검증 보고서를 따른다. 기준 확정, 코드 구현, 실제 환경 검증은 서로 다른 상태다.

## 단계별 확인 범위

| 영역 | 구현·기존 증거 | 남은 확인 |

| 기록·인증 서버, T01–T04 | 정규화, 임시 저장·명시적 등록, 권한·코드 인증, 공개 조회·정정·취소. [1단계 보고서](validation/stage1-report.md)에 실제 PostgreSQL·HTTP·JAR 복구 검사와 독립 검토 기록 | 실제 운영 환경의 준비 완료를 뜻하지 않음 |
| Windows 수집 흐름, T05–T07 | Electron 화면·로컬 SQLite 대기열·오프라인 재시도. [2단계 보고서](validation/stage2-report.md)에 단위·시험 응답·실제 Electron 검사 | 실제 Windows 인증 정보 보호·설치·업데이트와 대상 파일시스템 보존 확인 |
| 평가·추천·웹, T08–T12 | 포지션 평가·누적 통계·팀 추천·운영자 웹·영속 재계산. [3단계 보고서](validation/stage3-report.md)에 실제 서버 브라우저 검사와 별도 UI 상태 주입 검사 | 최종 계산 버전 반영·재계산, 외부 네트워크 운영자 접근 |
| 설치·배포, T13–T14 | 운영 방향은 확정했지만 실환경 수용 검증은 남음 | 아래 순서의 설치·업데이트·외부 접속·복원 확인 |

LCU는 League Client API(게임 클라이언트의 로컬 인터페이스), JAR는 자바 실행 묶음, CI는 변경마다 실행하는 지속적 통합 검사다. 시험 자료의 식별자·시각은 합성 또는 가명이다. 로컬·호스팅 시험 응답 성공을 실제 League·Windows 인증 보호나 운영 가용성 검증으로 확대하지 않는다. 테스트 개수와 실행 환경은 당시 보고서를 참조하며 여기서 최신 실행 수처럼 복사하지 않는다.

## 최근 오류 수정과 자동 검사

2026-10-26에는 [공개 후보 자료의 설명 파일 허용값 검사](https://github.com/SangHyeok0908/Civil-War/commit/7ee680d6da58f6302afad0ee3d666b552b3b0f7c)와 [늦은 목록 응답에 의한 수집기 등록 상태 역행 방지](https://github.com/SangHyeok0908/Civil-War/commit/9391475e48b62d5b1f1d370974b7b4058427e93e)를 반영했다. 기존 PR #1–#4는 순서대로 `master`에 병합했다. 이는 오류 수정과 개발 이력 통합이며, 위 표의 미완료 기능이나 실제 환경 검증을 완료한 것으로 바꾸지 않는다.

두 수정이 포함된 커밋 `eab0ed6`의 [서버·웹 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496591), [Windows 앱 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496596), [형식 검사](https://github.com/SangHyeok0908/Civil-War/actions/runs/40261496598) 성공을 확인했다. 서버·웹 검사는 실제 PostgreSQL과 브라우저를 사용하고, Windows 앱 검사의 게임 연결은 가상 응답이다. 기존 PR 4개를 병합한 커밋 `0df5352`의 파일 내용은 이 커밋과 같으며, 이번 문서 정리의 새 검사 결과는 해당 PR에 별도로 기록한다.

## 남은 작업 순서

1. 사용자 확정 평가 기준에 맞는 새 계산 버전 반영, 계약·화면 설명 갱신, 모든 유효 경기의 재계산·검증. 두 원본 피해 필드는 보존돼 있으므로 재수집을 전제로 하지 않는다.
2. Windows 설치·재설치·업데이트에서 인증 정보와 대기 자료 보존, 실제 보호 저장소 복호화 실패와 복구 확인(T13).
3. 집 Windows 서버의 외부 HTTPS·도메인·Tunnel 접속, 재부팅 후 복구, 프록시 환경 요청 제한, PC 밖 백업과 별도 DB 복원 확인(T14). T12의 외부 운영자 접근도 여기서 확인한다.

세부 수용 절차의 기존 근거는 [2단계 Windows 확인 항목](validation/stage2-report.md#exact-outstanding-windows-manual-run--hold)과 [당시 개발 계획의 설치·배포 작업](superpowers/plans/2026-10-21-lol-inhouse-development-plan.md#t13-windows-설치업데이트진단)이다. 새 작업을 시작할 때 이 문서의 최신 범위와 대조해 실행 계획을 작성한다.
